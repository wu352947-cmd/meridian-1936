## 1. 定位与一页纸概述（One-Page Overview）

### 1.1 核心愿景与原创 IP 定位
《子午线 1936：碎裂大陆》是一款面向桌面浏览器与平板设备的 **2D 可暂停即时制二战欧洲大战略网页游戏（1936–1945）**。玩家将在一张质感考究的“1930 年代参谋部亚麻硫酸纸作战地图”上，执掌欧洲主要大国或区域国家，统筹战前工业动员、科技攻关、国家方略抉择、危机外交与三军联合作战，亲历从战间期暗流涌动到全面大战终局的十年历史大变局。

本项目在设计哲学上精准锚定于《钢铁雄心 4》（*Hearts of Iron IV*）与《文明时代 3 / 历史时代 3》（*Age of History 3*）之间的黄金空白带：
- **保留《钢铁雄心 4》最令人着迷的“战争部长与战役指挥”灵魂**：战前扩建民用产能滚雪球、临战转产军工的宏观节奏，生产线熟练度权衡，看得见的连续战线与钳形突破包围，以及补给线对盲目深入的硬约束。
- **吸收《文明时代 3》的“清爽上手度与政治版图直觉”**：打开网页 10 秒即可开局，不规则省份政治色块一目了然，战斗修饰符与外交花费完全摆在明面，绝不逼迫玩家阅读几十页外部百科。
- **每个子系统均做定制度降维（约砍掉 HOI4 60% 的微观操作噪音）**：无 25 格师模板拼图、无坦克/飞机/舰船拧零件设计器、无间谍网小游戏、无 48 种琐碎商品图标，所有规则凝练为清晰、确定、可验证的数学公式。

### 1.2 核心玩法循环（Core Gameplay Loop）
游戏按**微观、中观、宏观**三层嵌套循环驱动玩家心流：
1. **微观循环（每数小时至数日 / 战时操作，约 15–60 秒现实时间）**：观察前线态势与补给染色 → 暂停时间（`Space`） → 框选集团军划定防守战线或钳形进攻箭头、调配空域中队夺取制空权 → 恢复 2x/3x 速度推进 → 监控交战气泡、侧翼包抄形成合围并歼灭敌军有生力量。
2. **中观循环（每 28–60 游戏日 / 内政与军备，约 2–5 分钟现实时间）**：签批下一项“国家方略（State Directive）”推进历史或架空分支 → 消耗行政点（AP）切换动员法案或外交担保 → 调整军工车间滑块弥补前线步枪/坦克库存缺口 → 在蓝晒科技图上指派新研发课题。
3. **宏观循环（整局战役 1936–1945，分三幕剧演进）**：
   - **第一幕：暗流与重整军备（1936.1–1939.8）**：欧洲危机度（Crisis Index）在局部事件中逐步攀升；各国扩建民用工坊、化解经济萧条或内部掣肘、构建三大阵营雏形。
   - **第二幕：闪击与战线拉锯（1939.9–1942.12）**：大战全面爆发，机动装甲集群寻求突破合围，防守方依托大河、山脉、要塞与焦土补给迟滞攻势，海空争夺封锁与反封锁。
   - **第三幕：总体战与终局条约（1943.1–1945.12）**：工业潜力与人力池深浅决定战略反攻能力，跨海两栖登陆开辟第二战场，直至敌方阵营核心国投降，召开战后和约会议重绘欧洲版图。

### 1.3 单局时长与目标玩家画像
- **单局标准时长**：
  - **1936《暗流涌动》完整剧本**：约 **2.5 – 4 小时**（战前备战约 35–45 分钟，全面战争约 1.5–3 小时，仅为同题材端游单局时长的 1/4）。
  - **1939《风暴前夜》开战剧本**：约 **1.5 – 2.5 小时**（跳过备战期，开局即进入波兰与西线军事博弈）。
  - **1940《西线闪击》快速教学微剧本（新手引导兼速通局）**：约 **30 – 45 分钟**。
- **目标玩家**：
  1. 热爱二战历史与地图涂色策略，但苦于传统端游动辄上百小时学习门槛与后期卡顿的**轻中度策略玩家**；
  2. 追求高审美界面质感（纸质制图美学、考究中文字体排版）、希望在笔记本浏览器或 iPad/平板上免安装随时游玩并存档的**中文策略核心受众**。

### 1.5 跨战区扩展预留与合规铁律
- **多战区架构前瞻（Theater Pack Architecture）**：所有地图几何、省份邻接图、剧本起始数据与方略树全部通过 `TheaterManifest` JSON 包解耦。当前交付 `europe_1936` 战区包；未来开发第二张地图 `pacific_1937`（亚太战区）时无需重写渲染器或模拟内核，且省份 ID 空间预留分段（欧洲 `1–1999`、亚太 `2000–3999`、美洲与非洲余部 `4000–5999`），并设计了“苏伊士/乌拉尔/大西洋航道”跨图边缘跃迁锚点（Off-map Transit Nodes），可直接无缝合流为全球战役。
- **严肃历史基调与合规铁律**：全游戏严禁出现纳粹卐字、SS 符文或旭日军旗；德国采用黑-白-红横三色旗 + 中心直臂铁十字（Balkenkreuz，用户 2026-11-25 已拍板），日本（外交引用及后续亚太包）一律采用白底红日章旗（Hinomaru）；行文严肃克制，聚焦宏观战略、工业组织与地缘博弈，绝不美化侵略或渲染暴行。

## 2. 技术栈选型与核心架构（Technical Architecture）

### 2.1 技术栈最终决策总览

针对“纯静态 GitHub Pages 托管 + 编码 Agent（Gemini 4 Neon XHigh）在无硬件 GPU 的 Linux Headless Chrome（SwiftShader）下截图自检 + 400~1000 不规则省份高频变色渲染 + 中文密集型策略面板”四大核心工程约束，本项目确定最终技术栈如下：

- **核心语言与构建**：**TypeScript 5.x（`strict: true`） + Vite 6.x**
- **2D 地图与态势渲染层**：**PixiJS v8（优先 WebGL2 管线，兼容 WebGPU，内置 Canvas/WebGL1 降级，完美适配 SwiftShader 软光栅）**
- **HUD 与策略面板 UI 层**：**Preact 10.x + `@preact/signals` + Tailwind CSS v4（配合自定义战时制图 CSS Token）**
- **模拟与 AI 计算层**：**独立 Web Worker + 纯 TypeScript 确定性整数/定点数状态机（TypedArray 扁平内存布局）**
- **本地存储与序列化**：**IndexedDB（`idb-keyval` 轻量封装） + `fflate`（Gzip/Deflate 高速压缩） + JSON/二进制双模导出**
- **自动化质量保障**：**Vitest（单元/确定性回放/无头 AI 百局自对弈） + Puppeteer（SwiftShader 确定性 URL 视觉回归截图）**

### 2.2 渲染引擎/框架逐项对比与否决理由（7 方案横评）

| 候选方案 | 结论 | 核心优势 | 被否决原因 / 关键短板（结合本项目与 Neon 沙盒约束） |
| :--- | :---: | :--- | :--- |
| **PixiJS v8 (WebGL2 / WebGPU)** | **最终采用** | 纯粹专注高性能 2D 场景图与自定义 Shader（Mesh/Filter）；包体轻量（gzip 约 130KB）；合批渲染数千战术计数器与动态战线毫无压力；在 Headless Chrome + SwiftShader 下帧率稳定、渲染结果像素级一致，最适合 AI Agent 编写直观的 TypeScript 渲染层代码。 | 无内置 UI 组件与物理引擎（本项目恰不需要物理引擎，UI 交由 HTML/Preact 覆盖层处理反而更擅长中文排版）。 |
| **Phaser 3 / 4** | 否决 | 内置场景管理、Tween、音效、输入与街机物理，小游戏开箱即用。 | 架构面向平台跳跃/RPG/弹幕游戏，大量物理、碰撞、帧动画模块在大战略地图中完全闲置（增加冗余包体至 300KB+）；其自定义多通道着色器（省份 ID 查表着色）不如 PixiJS v8 的 `Shader/GlProgram` 直观干净。 |
| **纯 Canvas 2D** | 否决 | 零第三方依赖，API 简单。 | **致命性能瓶颈**：每当缩放平移或省份易手时，用 CPU `ctx.fill()` 重绘 650+ 个多顶点不规则多边形并叠加边缘内发光、斜纹占领线，在平板高分屏（DPR≥2）上帧率极易跌破 25fps；且无法使用片元着色器做 O(1) 毫秒级切换 6 种地图模式。 |
| **Three.js（正交相机 2D）** | 否决 | 3D 生态成熟，`ShaderMaterial` 灵活，未来若加 3D 地形起伏有上限优势。 | 为纯 2D 纸质参谋地图引入完整 3D 渲染管线、光照材质与矩阵树属于过度设计；2D 文字抗锯齿、屏幕空间固定线宽（国界/战线缩放不糊）在 Three.js 中需额外引入 `Line2` 等扩展补丁，开发摩擦远高于 PixiJS。 |
| **Godot 4 Web 导出** | 否决 | 成熟一体化引擎，内置节点编辑器。 | **与部署及 Agent 工作流严重冲突**：① Godot 4 Web Wasm 空包即达 20–30MB，首屏加载慢；② 多线程导出强依赖 `SharedArrayBuffer`（GitHub Pages 原生不支持 COOP/COEP 响应头，单线程模式又易卡 UI）；③ 依赖 `.tscn` 图形编辑器场景文件，AI 编码 Agent 纯靠修改文本生成复杂大战略表格与中文富文本极易出错，SwiftShader 下 WebGL2 偶发兼容告警。 |
| **Bevy / Rust + WebAssembly** | 否决 | ECS 架构优雅，Wasm 模拟计算吞吐极高。 | **迭代周期与 UI 生态灾难**：在沙盒分批开发中，Rust 全量编译慢、Wasm 胶水层调试链长；Bevy 自身 UI 对复杂中文策略大表格、自适应折行、可访问性键盘导航支持远不如成熟 DOM；而我们的 6 小时 Tick 模拟在 TS TypedArray Worker 中每天耗时 <0.5ms，根本不存在非上 Rust 不可的算力瓶颈。 |
| **deck.gl / MapLibre GL** | 否决 | 地理信息（GIS）渲染强悍，天然支持矢量瓦片与 GeoJSON 图层。 | 它们是面向现代真实地球导航的 GIS 框架，强绑定墨卡托/球面瓦片坐标，难以自由定制“硫酸纸纹理 + 边缘水彩晕染 + 动态吞吐箭头 + 战术军牌碰撞避让”的游戏化着色器；且包体庞大（MapLibre/deck.gl 动辄 700KB+ gzip），离线自定义架空/亚太拼接战区受限于 GIS 规范。 |

### 2.3 UI 框架选型对比（DOM Overlay + Canvas 双层架构）

大战略游戏拥有大量高密度文本面板（国家方略树、7 类军需滑块、省份排序表、和约割地清单、多层数值拆解 Tooltip）。**绝对不要在 WebGL Canvas 内部手搓按钮、滚动列表与中文排版**，而应采用经典的 **“底层全屏 PixiJS Canvas（负责地图、边界、战线、部队计数器）+ 顶层指针穿透（`pointer-events: none`）HTML/CSS UI 层”** 架构：

1. **Preact 10.x + `@preact/signals`（最终采用）**：
   - **理由**：体积仅 **~4KB**，与 React JSX 生态和 TypeScript 类型 100% 契合，编码 Agent（Neon XHigh）生成 JSX 组件的准确率在所有前端方案中最高；配合 `@preact/signals` 实现细粒度响应式更新——当 Worker 每 Tick 推送新的日期、行政点或人力数字时，只有绑定该 Signal 的文本节点局部刷新，**零整棵虚拟 DOM 树重渲染开销**，完全不抢占地图渲染帧预算。
2. **React 18/19（否决）**：运行时约 45KB，高频 Tick 更新若稍有疏忽漏写 `memo` 极易触发大面板级联重绘，相较 Preact + Signals 无额外收益。
3. **Svelte 5 / SolidJS（否决）**：运行时性能同样极佳，但 Svelte `.svelte` 单文件模板语法或 Solid 严禁解构 Props 的编译期心智陷阱，在多批次 AI Agent 无人值守迭代中偶发隐蔽响应式丢失 Bug，工程稳健性略逊于标准 TSX + Signals。
4. **原生 DOM / Web Components（否决）**：手写命令式 DOM 拼接上百个外交条件、生产队列与过滤排序表格会导致状态同步面条代码，极难维护。

### 2.4 发布平台论证：GitHub Pages 静态托管与桌面端演进

- **为什么坚持纯静态站点部署于 GitHub Pages（`wu352947-cmd`）**：
  1. **零运维成本与永久高可用**：本作是纯单机大战略沙盘，全部模拟与 AI 在玩家浏览器本地 Worker 中闭环运行，无需任何后端数据库或联机匹配服；GitHub Pages 免费提供全球 Fastly CDN、HTTPS 与 GitHub Actions 自动构建发布。
  2. **分享即玩（Zero-Install）**：中文玩家点开链接 3 秒内即可看到欧洲参谋地图，存档保存在本地浏览器并可随时导出 `.m36save` 文件备份分享。
  3. **静态托管局限的规避方案**：GitHub Pages 有两处天然限制——① 仓库构建产物软限制 1GB、单文件 <100MB（本项目全量资源控制在 **<18MB**，首屏核心包 **<1.5MB**，绰绰有余）；② **不支持自定义 HTTP Header**（因此默认无 `Cross-Origin-Opener-Policy` / `Cross-Origin-Embedder-Policy`，默认禁用 `SharedArrayBuffer`）。正如 2.6 节将详述的，我们采用紧凑二进制快照/差量 `Transferable ArrayBuffer` 通信，**完全不依赖 `SharedArrayBuffer` 即可跑满性能**，无需使用会导致首次访问强制刷新白屏闪跳的 `coi-serviceworker` 黑科技。
- **未来桌面版无缝演进路线（Tauri v2 优于 Electron）**：
  - 架构在存储层抽象 `StorageAdapter` 接口。当未来需要发布 Steam / 独立桌面下载版时，直接用 **Tauri v2** 包裹同一套 Vite 构建产物：安装包仅 **~8–12MB**（Electron 则高达 120MB+），并可将存档直接桥接至操作系统本地文档目录。

### 2.5 高性能 2D 省份地图渲染管线（400–1000 不规则省份）

在欧洲战区约 **640 个不规则陆地省份 + 68 个海域分区**（以及未来全球战役 ~2,200 省）的规模下，若将每个省份实例化为独立的 `PIXI.Graphics` 多边形并在易手或切换地图模式时重绘顶点，会导致 Draw Call 飙升与锯齿接缝。本项目采用大战略引擎标准工业方案——**“双纹理查表片元着色器（Province ID LUT Shader）+ 拓扑边界矢量网（Topological Edge Mesh）”**，实现 **单次 Draw Call 完成全图省份填色、O(1) 切换地图模式、O(1) 鼠标拾取**。

#### 1. 省份 ID 索引图与 GPU 查表着色（LUT Shader）
- **离线烘焙静态纹理（4096 × 3072 PNG，无损压缩、严禁抗锯齿 `NEAREST` 采样）**：
  1. `province_id.png`：每个省份赋予唯一整数 `provId ∈ [1, 4095]`，编码进 RG 双通道（`R = provId & 0xFF`, `G = (provId >> 8) & 0xFF`，`0` 留给地图外黑边/不可通行极地），`B` 通道编码**距本省边界的归一化像素距离场（0~255，用于海岸线与省界柔和渐变）**。
  2. `terrain_relief.webp`（2048 × 1536）：离线由数字高程（DEM）与土地覆盖渲染出的**低饱和度参谋纸质阴影底图**（含山脉晕渲、森林点阵纹、浅滩等深线）。
- **运行时动态数据纹理（`DataTexture`，尺寸 `4096 × 1`，RGBA8，仅 16KB）**：
  - `uPrimaryColorTex`：记录每个 `provId` 当前主填充色（政治模式下为控制国或法理国主题色；补给模式下为绿→黄→红补给充裕度；工业模式下为工坊密度色阶）。
  - `uSecondaryColorTex`：记录次级状态色（当省份处于“军事占领未吞并”或“宣战预警”时，存放占领国颜色，`A` 通道标记状态掩码：位 0=斜纹占领，位 1=当前选中省脉冲高亮，位 2=战争迷雾降暗）。
- **片元着色器单通道合成公式**：
  - 采样 `province_id.png` 还原 `provId`；再以 `(provId + 0.5) / 4096.0` 采样一维 `DataTexture` 拿到主色 $C_1$ 与副色 $C_2$。
  - **战时水彩边缘内晕染（Inner Tint）**：读取邻近 4 像素（跨度随相机缩放自适应）检测是否跨国界；国界内侧 6~14px 处提高国家色彩不透明度（$\alpha = 0.72$），向国土腹地过渡为半透明（$\alpha = 0.36$），使底层的 `terrain_relief` 山脉阴影与亚麻纸纤维自然透出，兼具《钢铁雄心 4》的地形可读性与《文明时代 3》的版图清爽感。
  - **军事占领斜纹（Hatched Occupation）**：若 `secondary.a` 含占领标志，在屏幕像素空间按 `(gl_FragCoord.x + gl_FragCoord.y) mod 10 < 3` 交替混合法理国底色 $C_1$ 与占领国斜纹色 $C_2$，一眼区分本土与占领区。
  - **性能收益**：无论地图上有 600 省还是 3000 省，切换政治/地形/补给/工业等任意地图模式，主线程只需覆写 16KB 的 `Uint8Array` 并调用一次 `gl.texSubImage2D`，耗时 **< 0.15 ms**！

#### 2. 拓扑边界网格生成（国界、省界、海岸线、大河）
- 构建期利用 TopoJSON 共享弧段（Arcs）提取每条公共边 $(P_i, P_j)$，三角化为屏幕空间等宽丝带网格（Extruded Polyline Miter/Bevel Strip）：
  - **海岸线**：固定深褐墨线（`#2C2621`，1.6px）外加浅海双层波纹晕染。
  - **动态国界线**：维护弧段顶点属性 `ownerA / ownerB`；仅当两侧省份当前控制者不同时激活粗墨线（`#1E1A17`，2.2px）与外交选中朱砂外发光；同国境内的**省界线**则绘制为低对比度虚线/细灰褐线（0.7px），并在远景自动淡出。
  - **主要通航/天堑大河**（莱茵河、多瑙河、维斯瓦河、第聂伯河、伏尔加河等）：独立蓝灰墨线图层，宽度按干流/支流分级，作为跨河进攻惩罚的直观视觉依据。

#### 3. 语义缩放分级（4 级 Semantic Zoom LOD）
摄像机支持滚轮/双指平滑缩放（缩放比 `zoom ∈ [0.6, 6.0]`），严格定义四档视觉层级以防信息过载：
- **LOD 0 洲际战略层（`zoom < 1.1`）**：隐藏省界细线、省名与普通城市点；仅显示国家色块、粗国界、首都五角星、沿国土弯曲的大国名称，以及按战区自动聚合的**集团军总兵力大徽牌**。
- **LOD 1 战区战役层（`1.1 ≤ zoom < 2.2`，默认开局视角）**：淡入大河、重要胜利点城市（VP ≥ 5）、海空战区分割虚线、连续战线与进攻大箭头、省级堆叠军牌（显示主力旅图标 + 旅数量）。
- **LOD 2 前线战术层（`2.2 ≤ zoom < 3.8`）**：清晰展示省界细线、全部城市与港口/机场/要塞微缩符号、单个作战旅的双进度条（编制实力条 + 组织士气条）、交战气泡实时跳字与行军进度箭头。
- **LOD 3 参谋详查层（`zoom ≥ 3.8`）**：显示全部省份中文名、地形小角标与驻地补给余量百分比。

#### 4. 国名曲线排布（Curved Country Labels）
- 当国家版图因吞并或割让发生变化时（低频事件，仅在领土变更帧触发重算）：
  1. 对该国最大连通陆块多边形求多边形极点（`polylabel` 内切圆心）与二阶中心矩（PCA 主成分特征向量），拟合出贯穿国土狭长走向的**二次贝塞尔主脊曲线**（如意大利沿亚平宁半岛斜向排布、挪威沿海岸弧线排布）；
  2. 使用 PixiJS `BitmapText`（MSDF 预生成中英字符集或高分辨率离线 Canvas 贴图缓存）将国名字符沿贝塞尔弧长等距贴合旋转，字号随连通块包围盒面积自适应，加浅米色描边确保在深浅底色上均清晰锐利。

#### 5. 可见连续战线与进攻计划绘制（Frontlines & Battle Arrows）
- **连续战线几何提取**：当集团军绑定敌国边境时，直接从拓扑图检索双方接壤的所有共享弧段 `Arc`，通过端点哈希拼接为连续折线链（Polyline），向己方一侧法向偏移 3px 绘制**带齿状刻度与集团军代表色的参谋战线**（无须手绘歪斜线条）。
- **钳形进攻箭头**：玩家在战线上拖拽指向目标省份（如华沙、巴黎）时，以起点战线中点、途径控制点与终点省中心生成平滑三次贝塞尔宽带网格，片元着色器叠加沿 `UV.x` 缓慢流动的半透明斜向条纹，执行进攻期间流速加快，停止计划时呈静止虚线。

#### 6. O(1) 零射线检测拾取（Pixel-Perfect Picking）
- 内存常驻一份降采样 2 倍（`2048 × 1536`）的 `Uint16Array` 省份 ID 栅格（仅占 `6.2 MB` RAM）。鼠标移动或手指点击屏幕坐标 $(x, y)$ 时，经摄像机逆矩阵变换为地图世界坐标 $(u, v)$，直接做一次数组下标读取 `provGrid[v * 2048 + u]`，**耗时 < 0.001 ms**，无需对 640 个不规则凹多边形做复杂的点在多边形内几何计算。

### 2.6 确定性模拟层架构（Web Worker + 定点数状态机）

为彻底杜绝大战略游戏常见的“后期 AI 思考卡顿导致地图拖动掉帧”以及方便自动化回放回归测试，**全部游戏逻辑、战斗结算与 AI 决策 100% 运行在独立 `SimulationWorker` 线程中**，主线程仅负责 PixiJS 渲染、音效播放与 Preact UI 采集指令。

#### 1. 100% 确定性定点运算（Deterministic Fixed-Point Math）
- **严禁在模拟层使用原生浮点超越函数**（`Math.sin/cos/pow/random` 在不同 CPU 架构或 JIT 优化下存在尾数微小漂移）：
  - 所有比率、效率、组织度、战斗力与资源库存统一采用 **千分比/万分比 32 位有符号整数（`Int32` 定点数，缩放因子 `SCALE = 1000`）**。例如：稳定度 `75.4%` 存储为整数 `754`；生产线效率 `62.5%` 存储为 `625`；乘法修正统一使用整数公式 `Math.imul(a, b) / 1000 | 0`。
- **可复现伪随机数生成器（Seeded PRNG）**：
  - 采用纯 32 位无符号整数位运算的 **`sfc32` / `mulberry32`** 算法，状态仅占 4 个 `uint32` 字（随存档完整保存）。严禁任何 UI 悬停或音效逻辑读取模拟器的 PRNG，确保**“相同初始剧本 + 相同随机种子 + 相同带 Tick 戳的玩家指令序列 = 经过 5000 个 Tick 后状态 SHA-256 哈希 100% 逐字节一致”**。

#### 2. 时间步与指令队列（Tick & Command Queue）
- **基础时间原子**：`1 Tick = 6 游戏小时`（`00:00` 晨、`06:00` 午、`12:00` 昏、`18:00` 夜；`4 Ticks = 1 游戏日`，1936-01-01 至 1945-12-31 共 `3650 天 = 14,600 Ticks`，固定无闰日简化日历或精确格里高利历统一查表）。
  - **每 Tick（6 小时）结算**：陆军跨省行军进度、活跃陆战攻防与士气损耗、空战截击修正。
  - **每日（每 4 Ticks，`00:00`）结算**：工业产出与建造进度、方略树与科研天数递减、补给网络 BFS 刷新、伤亡兵员补充、占领区抵抗涨落、分批轮询国家 AI。
- **单向命令流（Command Pattern）**：
  - 玩家在 UI 上的任何操作（如指派方略、拖动军工滑块、划定战线、宣战）均封装为纯 JSON 可序列化结构 `GameCommand { tick: number; actorTag: string; type: CommandType; payload: unknown }` 发送给 Worker。Worker 在对应 `tick` 头部按序校验合法性并应用到 `WorldState`，既天然生成完整战局录像（Replay Log），又杜绝主线程与模拟线程竞态修改数据。

#### 3. 主线程 ↔ Worker 数据传输：评估 GitHub Pages 下的 `SharedArrayBuffer`
- **GitHub Pages 环境限制深度评估**：
  - 现代浏览器启用 `SharedArrayBuffer`（SAB）强制要求服务端返回 `Cross-Origin-Opener-Policy: same-origin` 与 `Cross-Origin-Embedder-Policy: require-corp` 响应头，而 **GitHub Pages 不支持自定义 HTTP 响应头**。
  - 业界虽有开源补丁 `gzuidhof/coi-serviceworker`（首次加载注册 Service Worker 拦截请求注入 COOP/COEP 头并强制 `location.reload()`），但它带来两个明显工程代价：① 玩家首次点开网页会经历一次突兀的二次刷新闪跳；② 某些无痕窗口、企业内网策略或嵌入式 WebView 会禁用 Service Worker 控制权，导致游戏直接无法启动。
- **架构拍板：零拷贝双缓冲 `Transferable ArrayBuffer` 快照流（无需 SAB）**：
  - 我们精确核算单帧需同步给渲染层的热数据规模：
    - 750 个省份状态（控制国 `uint16` + 法理国 `uint16` + 补给值 `uint8` + 抵抗度 `uint8` + 建筑摘要 `uint16`）= `750 × 8 B = 6 KB`；
    - 最多 800 个在图作战旅（所在省 `uint16` + 目标省 `uint16` + 行军进度 `uint8` + 模板与国籍 `uint16` + 实力百分比 `uint8` + 士气百分比 `uint8` + 状态位 `uint8`）= `800 × 12 B = 9.6 KB`；
    - 最多 60 场活跃战斗气泡 + 40 个国家宏观顶栏摘要 = `~8 KB`。
  - **总计单 Tick 视图快照仅约 `24 KB`！** 采用预先分配的 2 块 `32 KB ArrayBuffer` 在主线程与 Worker 之间通过 `postMessage(buf, [buf])` **乒乓移交所有权（Ping-Pong Transferable）**，单次跨线程转移耗时 **< 0.03 ms**，零 GC 垃圾回收压力；低频大文本数据（如点开某国外交详情或科技树状态变化）才附加轻量差量 JSON Patch。这套方案在普通 HTTP、GitHub Pages、本地文件预览、平板 Safari 与 Puppeteer 无头沙盒中 **100% 原生免配置运行**。

### 2.7 存档系统设计（版本化、压缩、存储介质与迁移）

#### 1. 本地存储介质三选一对比
| 存储 API | 容量上限 | 同步/异步 | 适用定位与本项目分工 |
| :--- | :--- | :--- | :--- |
| **`localStorage`** | ~5 MB | 同步阻塞 | **仅存用户偏好设置**（音量、色盲模式开关、上次游玩槽位 ID、教程完成标记，`< 4 KB`），绝不存游戏大存档以免阻塞主线程或爆容量。 |
| **`IndexedDB`** | 数百 MB ~ 数 GB | 异步非阻塞 | **主力存档仓库（最终采用）**。在 Chrome/Firefox/Safari（含 iPadOS）兼容性极稳，支持直接存取压缩后的 `Uint8Array` 二进制块，默认提供 **1 个自动存档槽（每游戏月 1 日滚动覆盖，保留最近 3 份）+ 20 个手动命名存档槽**。 |
| **`OPFS` (Origin Private File System)** | 数 GB | Worker 内可同步 | 在部分旧版移动端 WebKit 存在细节差异，且对几百 KB 的策略存档无显著优势，故不作为强依赖。 |

#### 2. `.m36save` 存档格式与跨版本迁移
- **文件结构**：采用 `Header + Compressed Payload` 封装。前 64 字节为明文 JSON 元数据头（无需解压即可在读档列表中秒级展示剧本名、扮演国家国旗、游戏内日期 `1941-06-22`、游戏版本号 `schemaVersion: 3`、真实保存时间戳）；主体为序列化 `WorldState` + 历史 `CommandLog`（可选勾选是否含回放日志），经 **`fflate.gzipSync`（纯 JS 仅 8KB）** 压缩后，完整一局存档体积仅 **80 KB – 220 KB**。
- **文件导入/导出**：读档面板提供“导出 `.m36save` 到本地磁盘”与“拖拽/选择 `.m36save` 导入”按钮，方便玩家跨设备传档或向开发者提交复现 Bug 的现场存档。
- **版本迁移管道（Migration Pipeline）**：代码库维护纯函数链 `migrations: Record<number, (raw: any) => any>`（如 `v1 -> v2` 补齐新增空域字段默认值、`v2 -> v3` 转换旧资源枚举）。读取低版本存档时自动按序升级至最新 `CURRENT_SCHEMA_VERSION`，若大版本不兼容则在 UI 友好提示而非白屏崩溃。

### 2.8 多维自动化测试与无头验证体系

为支撑 `Gemini 4 Neon XHigh` 在多批次开发中自主发现并修复逻辑与渲染缺陷，工程内置四层自动化防线：
1. **核心公式单元测试（`npm run test:unit` / Vitest）**：对陆战伤害公式、宽度超限惩罚、包围判定、补给 BFS 衰减、产线熟练度增长、科技跨年惩罚、和约分值计算编写边界用例，要求 `src/sim/` 核心规则分支覆盖率 **≥ 85%**。
2. **确定性回放一致性测试（`npm run test:determinism`）**：固定种子 `seed = 19360101` 并注入 50 条预设玩家/AI 混合指令，连续跑两遍 720 Ticks（半年），断言最终 `WorldState` 序列化字节流的 SHA-256 完全相等；同时验证在 `tick = 360` 处存档再读档续跑至 `720`，其哈希与不中断连跑完全一致（消灭“读档丢失临时状态”顽疾）。
3. **无头 AI 全局自对弈压力与平衡测试（`npm run sim:headless`）**：在纯 Node.js 进程中脱离浏览器全速运行 `SimulationWorker` 内核（跑完 1936–1945 全程 14,600 Ticks 在 Node 下仅需 **~1.8 秒**），连跑 10 局不同种子，自动断言：无 `NaN`/负数人力/工厂溢出异常、二战在 1938–1941 年间正常爆发、无单一阵营在 1940 年前异常速推全图。
4. **Puppeteer + SwiftShader 确定性视觉回归检查（`npm run test:visual`）**：启动带 `--use-gl=angle --use-angle=swiftshader --window-size=1440,900` 参数的无头 Chromium，访问内置调试查询参数（如 `?scenario=1936&country=GER&mapmode=political&date=1936-01-01&autotest=1`），等待 `window.__MERIDIAN_READY__ === true` 后自动截取各视角与 UI 面板 PNG，供 Neon XHigh 亲眼读取图片自检排版溢出、文字重叠或着色器黑块。

### 3.2 地图投影与欧洲裁切范围（Projection & Extent）

- **选用投影**：**欧洲等积方位投影（Lambert Azimuthal Equal-Area, LAEA Europe, `EPSG:3035`）**，投影中心设为 `(λ₀ = 10°E, φ₀ = 52°N)`（德国中部汉诺威附近）。
  - **为什么不用 Web 墨卡托（EPSG:3857）或等距圆柱投影（EPSG:4326）？**
    墨卡托投影在高纬度会产生灾难性的面积膨胀（芬兰、挪威、苏联北部看起来比法国和西班牙加起来还巨大），严重扭曲战略纵深与玩家对东线/北欧距离的直觉；而 **LAEA 等积投影** 保证了全欧洲从北非突尼斯到北极圈摩尔曼斯克的**真实面积比例严格一致**，且大西洋—地中海—乌拉尔山呈现极具大战略古典美感的微弧形球面张力。
- **战区地理裁切框（Projected Bounding Box）**：
  - 覆盖完整的欧洲大陆及二战欧洲战区联动周边：**西起冰岛与大西洋中部海盆（25°W），东抵乌拉尔山脉西麓与里海西岸（54°E，涵盖莫斯科、斯大林格勒、高加索巴库油田），北达北角与摩尔曼斯克（71°N），南括法属北非、意属利比亚、英控埃及苏伊士运河及中东叙利亚/伊拉克西部（29°N）**——确保北非拉锯战、地中海封锁、大西洋护航战与东线大纵深全部在同一张无缝地图内闭环呈现！
  - 画布统一归一化映射至 **`4096 × 3072` 像素世界空间（宽高比 4:3）**。

### 3.3 从现代 Admin-1 清洁重构 1936 历史版图的算法规则

由于现代国界（2020s）与 1936 年存在若干关键历史差异，离线脚本 `tools/map-compiler/` 通过 **“Natural Earth `admin-1` 州省多边形聚合 + 河流/经纬切割刀（Polygon Splitters）”** 纯净生成 1936 年政治地图：

1. **以州省积木重组历史国界（零手工描边侵权风险）**：
   - **德波边界与东普鲁士（1936）**：将现代波兰的西波美拉尼亚、卢布斯卡、下西里西亚、奥波莱及瓦尔米亚-马祖里（南东普鲁士）与俄罗斯加里宁格勒州（北东普鲁士/柯尼斯堡）按现代省级边界直接划归 `GER`；将波美拉尼亚省沿维斯瓦河西岸切出狭长的“波兰走廊”归属 `POL`，切出**但泽自由市（Danzig）**独立微省（由波兰关税保护或并入波兰走廊核心争议省）。
   - **波兰第二共和国东部（Kresy）与波罗的海**：将现代白俄罗斯西部（布列斯特、格罗德诺州）与乌克兰西部（沃伦、利沃夫、捷尔诺波尔、伊万诺-弗兰科夫斯克州）划归 `POL`；维尔纽斯地区划归 `POL`（立陶宛临时首都设于考纳斯 `Kaunas`）。

   - **芬兰与卡累利阿地峡**：将现代俄罗斯列宁格勒州北部的维堡（Viipuri / 卡累利阿地峡）及佩察莫走廊划归 1936 年的 `FIN`，使列宁格勒紧邻芬兰边境，还原冬季战争的战略动因。
   - **罗马尼亚大一统版图（Greater Romania）**：将现代摩尔多瓦全境及乌克兰切尔诺夫策/南比萨拉比亚划归 `ROM`。
   - **北非与地中海殖民地**：摩洛哥北部划归西班牙（`SPR` 西属摩洛哥，作为西班牙内战事件起爆点），阿尔及利亚与突尼斯划归 `FRA`，利比亚与多德卡尼斯群岛划归 `ITA`，马耳他、直布罗陀、塞浦路斯、埃及-苏伊士运河区划归 `GBR`（或英国保护国控制）。
2. **多边形融合与拓扑简化（Mapshaper 管线）**：
   - 现代欧洲 `admin-1` 共有 1,800+ 个细碎行政区（例如斯洛文尼亚、卢森堡或瑞士各州过小），脚本读取声明式映射表 `data/raw/province_merge_1936.json` 将过小县市按面积阈值合并，对过大州（如苏联中部大州、西班牙卡斯蒂利亚）按大河与交通枢纽对半拆分，控制所有陆地省份面积处于均衡区间。
   - 调用 `mapshaper -simplify visvalingam 8% keep-shapes -clean` 执行保拓扑简化：消除海岸线细碎锯齿，确保任意两相邻省份共享完全重合的顶点序列，零裂缝、零重叠。

### 3.4 目标省份规模与 1936 欧洲各国分布规划

为什么把欧洲陆地省份定在 **`640` 个左右**（外加 **`68` 个海区**，合计 **`708` 个地图单元**）？
- 若少于 200 省（如传统桌游《轴心国与同盟国》），法德边境或苏德前线只有 2~3 格宽，根本无法拉出连续战线与钳形合围，退化为单点对撞；
- 若像端游那样塞入 4,000+ 欧洲省份，网页端每帧视口内拥挤上百个微型军牌，玩家微操疲劳剧增且 AI 寻路开销翻十倍；
- **`640` 陆地省**恰好让法比卢西线正门拥有 **9–11 省宽度**（足以区分阿登森林奇袭、马奇诺死守与低地平原包抄），苏德东线从波罗的海到黑海拥有 **18–22 省正面与 8–10 省战略纵深**，既能爽快打出明斯克/基辅式大合围，又能在 3 小时内痛快打完一局！

同时引入两层聚合容器：每 **3–5 个相邻陆地省** 组成一个 **行政工业区（Region，共 155 个，工厂与基础设施建在行政区上，避免逐省点建筑）**；每 **8–12 个海区或 25–40 个陆地省** 归属一个 **战略海空区（Strategic Zone，共 18 个陆空区 + 10 个大洋海区）**。

### 3.5 海域分区与五大战略海峡（Sea Zones & Straits）

- **68 个海域格**按洋流与作战半径切分，归入 **10 个大洋海战区**（如英吉利海峡、北海、波罗的海、比斯开湾、西地中海、中地中海、东地中海、黑海、挪威海、北大西洋航道）。
- **两类海峡机制**：
  1. **陆军跨海渡口（Land Crossing Straits）**：如西西里—意大利本土（墨西拿海峡）、丹麦日德兰—哥本哈根群岛、爱沙尼亚岛屿、克里米亚刻赤海峡。陆军可直接徒步跨海进攻（承受 `-35%` 渡海惩罚），但**若敌方舰队在该海区拥有制海权（>50% 控制度），渡口即被封锁禁行**。
  2. **海权咽喉运河（Naval Chokepoints）**：**直布罗陀海峡、苏伊士运河、丹麦厄勒海峡、土耳其博斯普鲁斯海峡**。只有控制沿岸要塞省的一方及其盟友/中立船队可通过，交战敌方水面舰队禁止通行（潜艇仅在直布罗陀/丹麦海峡可以高风险潜航渗透）。

### 3.6 省份与行政区属性生成与手工精校规则

每个省份/行政区的数据遵循 **“GIS 自动采样打底（80% 工作量）+ 历史考据表覆盖（20% 关键点）”**：
1. **7 种地形自动判定**：脚本采样 Natural Earth 高程（DEM）与土地覆盖栅格——海拔 `>1200m` 为 **`mountain`（高山）**，`500–1200m` 或起伏度高为 **`hills`（丘陵）**，针阔叶林占比 `>45%` 为 **`forest`（森林）**，普里皮亚季/三角洲湿地为 **`marsh`（沼泽）**，北非内陆/中东干旱区为 **`desert`（荒漠）**，伦敦/巴黎/柏林/鲁尔/莫斯科/列宁格勒/斯大林格勒/华沙/罗马/维也纳等 38 座核心大都市手工覆写为 **`urban`（都市）**，其余为 **`plains`（平原）**。
2. **跨河边属性（River Crossings）**：将 Natural Earth 1:10m 主要河流矢量与省份公共边做缓冲区求交，重合长度超过边长 40% 的邻接对 `(provA, provB)` 自动标记为 `major_river`（大河）或 `minor_river`（支流）。
3. **胜利点（VP）、港口、工业槽与资源**：由纯文本配置表 `data/europe_1936/regions_override.csv` 驱动，依据 1936 年各国真实钢铁/原油产量与人口统计按比例缩放到游戏整数数值（详见 4.12 节各国开局配平表）。

### 3.7 离线地图编译管线与产物格式

所有重型 GIS 处理在开发期通过 `npm run build:map`（Node.js 22 脚本：依赖 `mapshaper`、`@turf/turf`、`polylabel`、`sharp`、`canvas`）一次性离线完成，**严禁把几十 MB 的原始 Shapefile 打包进前端运行时**！最终输出到 `public/assets/maps/europe_1936/` 的运行时产物总计仅 **`~2.6 MB`**：
- `topology.topo.json`（`~420 KB`，gzip 后 `~135 KB`）：包含 708 个省海区的简化拓扑弧段、每个弧段的左右省份 ID 与河流等级，供前端启动时构建边界丝带 Mesh 与战线折线。
- `province_graph.bin`（`~38 KB` 二进制）：紧凑 CSR 邻接表、各省质心坐标 $(cx, cy)$、地形枚举、所属 Region 与 Strategic Zone 索引，供 Worker 毫秒级加载寻路。
- `province_id.png`（`~950 KB` 无损索引 PNG，`4096×3072`）：供 GPU LUT 着色器查表与降采样拾取。
- `terrain_relief.webp`（`~1.2 MB`，`2048×1536`）：烘焙好纸张纤维、等高晕渲与浅海阴影的静态底图。

## 4. 完整核心系统设计（规则、数据结构、公式与精简对照）

本章为编码 Agent 提供**可直接翻译为 TypeScript 代码**的精确规则集。所有涉及比率的计算在 `SimulationWorker` 中均以千分比整数（`1000 = 100.0%`）执行。

### 4.1 时间、季节气候与倍速控制（Time & Weather）

- **玩家可见规则**：
  - 时间自剧本起点（`1936-01-01 00:00` 或 `1939-09-01 00:00`）按 **6 小时一跳（Tick）** 推进：`00:00（拂晓）→ 06:00（正午）→ 12:00（黄昏）→ 18:00（夜间）`。其中 `18:00` 夜间 Tick 陆战双方攻击力统一乘 `0.75`，空军出动率乘 `0.50`。
  - **五档时间控制**：`暂停 (Space)`、`1x（每 800ms 1 Tick，细品微操）`、`2x（每 350ms 1 Tick，常规作战）`、`3x（每 120ms 1 Tick，战线推进）`、`4x 极速（每 25ms 1 Tick ≈ 每秒 10 游戏日，战前种田备战）`。遭遇重大外交最后通牒、本土被宣战或首都濒危时自动弹出电报并强制切回暂停。
  - **区域季节气候（Seasonal Climate）**：摒弃逐省随机小时级云雨模拟，改为按纬度/地理气候带（西欧温带、地中海/北非干旱带、北欧亚寒带、东欧大陆性气候带）与月份确定性触发：
    - **春秋泥泞季（东欧 4 月、10 月下半月）**：东欧气候带省份陆军行军速度 `-40%`、装甲/摩托化旅进攻 `-35%`（直观呈现“翻浆期 Rasputitsa”）。
    - **严冬期（东欧与北欧 12 月–次年 2 月）**：非山地旅进攻 `-25%`，缺补给损耗翻倍，芬兰/苏联拥有固有抗寒修正抵消一半惩罚。
- **数据结构**：`ClockState { tick: number; speed: 0|1|2|3|4; pausedByModal: boolean }`（日期由 `startEpoch + tick * 6h` 纯函数推导）。
- **UI 入口 & AI 使用**：右上角“参谋怀表与日历牌”点击或按 `Space / 1~4` 切速，地图边框四角随严冬/泥泞浮现淡淡冰霜或泥印提示；AI 在东欧严冬与泥泞月自动下调大规模装甲总攻权重（乘 `0.4`），避免无脑送人头。
- **相比 HOI4 精简了什么**：将 1 小时步进合并为 **6 小时步进**（模拟吞吐提升 4 倍，消除繁琐小时级闪烁），砍掉复杂的气压锋面流体天气模拟，保留最具战略体感的大陆泥泞季与严冬。

### 4.2 国家、中性政体谱系与三大国力指标（Nation & Governance）

- **玩家可见规则**：
  - **四种中性命名的政体/治理体制（Regime Types）**（摒弃情绪化标签且规避单一路线无脑强，每种体制各有鲜明机制红利与约束）：
    1. **议会宪政制（Constitutional Republic，蓝，`GBR/FRA/BEL/HOL/CZE/SWE` 等）**：社会凝聚度上限高、科研速度 `+8%`、贸易信用极佳；但在 **欧洲危机度 < 50%** 时无法主动对无领土纠纷国制造宣战理由，且切换高级动员法案需更高危机度门槛。
    2. **集权军国制（Militarist Autocracy，深铁灰，`GER/ITA/HUN` 等）**：制造宣战理由耗时 `-50%`、不受危机度低谷限制、初始陆军计划上限 `+15%`；但和平时期社会凝聚度自然衰减，且被敌军攻入核心本土时凝聚度崩盘速度加倍。
    3. **计划动员制（Planned Collectivism，绛红，`SOV` 等）**：大型重工建设槽位 `+1`、战略资源自给加成 `+15%`、人力动员池深厚；但初期生产熟练度起步上限较低，需通过国家方略完成工业与军官团整肃。
    4. **威权保守制 / 严守中立（Authoritarian / Neutrality，赭褐，`POL/ROM/YUG/FIN/TUR/SWI` 等）**：核心领土防御 `+15%`、驻军维持消耗 `-20%`，可在危机升级后通过国家方略转向另外三大阵营路线。
  - **三大顶栏核心软指标**：
    - **行政点（Administrative Points, `AP`，范围 `0–999`）**：每日基础产出 `+2.0`，受国家方略与凝聚度修正（公式：$\Delta AP = 2.0 \times (0.8 + 0.4 \times \text{Cohesion})$），用于颁布法令、签署外交条约与任免参谋学派。
    - **社会凝聚度（Cohesion，`0%–100%`）**：衡量国内秩序与工业运转效率。高于 `50%` 时每 `+10%` 提供 `+4%` 工厂产出与 `+5%` 抵抗镇压；低于 `50%` 时按同等斜率扣减产出并加速投降阈值。
    - **战时动员度（War Readiness，`0%–100%`）**：衡量国民投入总体战的意愿，决定能否解锁“战时经济”与“广泛征兵”，并在核心领土作战时提供最高 `+10%` 部队士气恢复。
- **数据结构**：
  ```ts
  interface NationState {
    tag: NationTag; regime: 'republic' | 'autocracy' | 'collectivist' | 'neutral';
    ap: number; cohesion: number; readiness: number; // 定点整数 0..1000
    factionId: FactionId | null; isMajor: boolean; capitulated: boolean;
  }
  ```
- **UI 入口 & AI 使用**：屏幕顶部左侧“国情公文签”实时展示三指标及每日增减悬停拆解；AI 根据预设战略人格（史实路线或分支权重）在 `AP ≥ 120` 时优先升级经济与征兵法令。
- **相比 HOI4 精简了什么**：砍掉几十个零散的内阁部长、军工组织（MIO）、理论家与政党支持率圆饼图微操，浓缩为“政体固有特性 + 3 项政务法令槽”，并赋予议会宪政国家科研与盟友工业协同优势，纠偏“独裁政体单方面碾压”的失衡设计。

### 4.3 外交、欧洲危机度与三大阵营体系（Diplomacy & Factions）

- **玩家可见规则**：
  - **欧洲危机度（Crisis Index，`0%–100%`）**：全局温度计。1936 开局为 `5%`；每次领土索取事件（如莱茵兰 `+5%`、吞并奥地利 `+10%`、苏台德 `+15%`）、制造宣战通牒（`+8%`）或正式宣战（大国宣战 `+20%`）都会推高危机度，每年和平期仅自然回落 `-2%`。危机度达到 `25% / 50% / 75%` 分别解锁议会宪政国家的整军方略、独立担保与主动入盟权限。
  - **8 项精炼外交行动**（关系值范围 `[-100, +100]`）：
    1. **派驻使团改善关系**（持续每日 `-0.2 AP`，每月关系 `+12`，上限 `+60`）；
    2. **互不侵犯条约**（消耗 `25 AP`，12 个月内双方不得直接宣战，违约撕毁需至少提前 60 天且危机度 >60%、扣减自身 `15%` 凝聚度）；
    3. **军事通行权**（消耗 `15 AP`，允许陆军借道但不允许从借道中立国直接向敌国发起越境进攻，防止无赖借道偷袭）；
    4. **独立担保（Guarantee）**（消耗 `40 AP`，宪政大国在危机度 `≥25%` 可用；目标国若遭第三方进攻，担保国自动收到参战电报，履行承诺加 `+10%` 动员度，背弃扣 `-20%` 凝聚度）；
    5. **战略物资禁运**（消耗 `30 AP`，关系 `≤ -40` 可用，切断目标国对本国钢铁/原油的贸易采购）；
    6. **租借军需援助（Lend-Lease）**（战时同阵营或对抗共同敌人可用，每月从本国军需仓库定量划拨步枪/卡车/坦克支援盟友）；
    7. **阵营邀约 / 申请加入**：默认三大阵营框架为 **协约同盟（Allied Entente，英法领衔）**、**中欧钢铁同盟（Central Pact，德意领衔）**、**东方共同体（Eastern Comintern，苏联领衔）**，主要大国亦可通过架空方略自建阵营（如法国小协约国、波兰海间联邦）；
    8. **拟定最后通牒与宣战（Ultimatum / Declare War）**：除方略树直接赋予的历史宣战权外，手动拟定宣战需消耗 `50 AP` 并经历 `60 天`（军国制 `30 天`）公开筹备期，期间目标国与担保国收到预警可提前布防。
- **数据结构**：`DiplomaticMatrix` 采用稀疏键值表 `Map<PairKey, RelationRecord>` 记录双边关系、条约到期 Tick 与禁运掩码；`WarRecord` 记录参战攻守阵营列表及各国累计战争贡献分（War Score）。
- **UI 入口 & AI 使用**：点击地图任意外国领土或按 `F2` 打开右侧外交抽屉（同时在地图上用朱砂圈选该国，宣战确认窗自动预览连锁参战国名单）；AI 用确定性评分函数 `acceptScore = base + 0.5*opinion + regimeAffinity + threatFactor - distancePenalty > 0` 决定是否接受条约，玩家可在按钮 Tooltip 上清楚看到每一项加减分（零黑盒拒绝）。
- **相比 HOI4 精简了什么**：砍掉武官派遣、意识形态颠覆政变、许可证生产与间谍外交，用完全透明的评分拆解替代模糊外交概率。

### 4.4 国家方略树（State Directives）与政务法令系统

- **玩家可见规则**：
  - **原创概念“国家方略（State Directives）”**：每个国家在同一时刻可签批推进 **1 项国家方略**，标准耗时分为 **28 天（短期对策）** 与 **42 天（重大国策）** 两档（比端游动辄 70 天等待更紧凑爽快）。推进期间每日自动消耗 `0.5 AP`；若中途主动中止，退还已走天数的 50% 并不返还 AP。
  - **专属方略树与通用方略树规模（内容量可控且重玩性饱满）**：
    - **6 个核心专属树国家（各 `20–24` 个节点）**：均按 **“经济重整支线（6~7 节点）+ 三军改革支线（6~7 节点）+ 地缘外交与战争支线（8~10 节点，含 1 组历史/架空互斥分叉 `[!]`）”** 构建：
      - **德意志（`GER`，24 节点）**：四年工业计划 / 合成燃油工程；机动装甲学派；莱茵兰重武装 → 德奥合并 → 苏台德危机 → 但泽最后通牒 → 西线黄案 / 东线攻略（*架空互斥分支*：遏制激进扩张、重建中欧防务同盟对抗东方）。
      - **大不列颠（`GBR`，22 节点）**：影子工厂计划 / 雷达防空链；皇家海空协同；绥靖克制（危机度 ≥25% 解锁重整军备）→ 担保波兰 → 地中海与大西洋护航 → 诺曼底开辟第二战场（*架空互斥分支*：帝国孤立防御与大陆均势干涉）。
      - **法兰西（`FRA`，22 节点）**：化解政治僵局（消除初期凝聚度惩罚）/ 扩建阿尔卑斯与马奇诺防线；装甲师独立建制改革；巩固英法同盟 vs **小协约国主动东进体系**（架空互斥：在慕尼黑危机中强硬保卫捷克斯洛伐克，提前引爆 1938 德法战争）。
      - **苏联（`SOV`，24 节点）**：五年重工东迁乌拉尔 / 矿冶扩产；军官团整肃与重建（短期降低组织度上限，完成后解锁大纵深反击红利）；集体安全外交 vs 东方缓冲带条约 → 卫国总体动员。
      - **意大利（`ITA`，20 节点）**：波河工业整合 / 地中海船坞扩建；北非公路补给线；钢铁盟约 vs **罗马多瑙河独立阵营**（架空互斥：拉拢奥匈保保持中立或背刺争霸地中海）。
      - **波兰（`POL`，20 节点）**：中央工业区（COP）建设；华沙筑垒与反坦防线；依托西方担保 vs **海间联邦（Międzymorze）**（联合波罗的海与罗马尼亚自建第四阵营）。
    - **区域国家通用方略树（`16` 个节点）**：供西班牙、捷克斯洛伐克、罗马尼亚、匈牙利、芬兰、南斯拉夫、土耳其、瑞典等全部次要国家使用，涵盖本土工业扩容（+3 民工/+3 军工）、额外科研槽解锁、国土防卫加成，以及自由选择靠拢三大阵营或武装中立。
    - **常设方略（Standing Directives，4 项）**：当本国已完成 ≥10 个方略节点后解锁，不限次数持续生效直至切换：`军工超负荷运转（军工产出 +10%）`、`战伤工程抢修（建筑修复速度 +50%）`、`海空护航建造（船坞产出 +15%）`、`绥靖抚慰占领区（全占领地抵抗每日 -0.3%）`。
  - **三槽政务法令（Governance Laws，每项切换消耗 `100 AP`）**：
    1. **经济动员法（4 级）**：`民用常态经济`（生活消费品占用民用工坊 **35%**） → `早期动员`（占用 **25%**，危机度 ≥15% 可点） → `战时经济`（占用 **15%**，军工建造速度 +15%，处于战争或动员度 ≥50%） → `总体战动员`（占用 **10%**，军工产出 +10%，适役人力上限 `-1.5%`，仅限与大国交战时）。
    2. **兵役征召法（4 级）**：详见 4.7 节人力系统（`志愿兵役 1.5%` → `有限征兵 3.0%` → `广泛征兵 6.0%` → `倾国动员 10.0%`）。
    3. **战略贸易法（3 级）**：`自由出口`（本国资源 50% 挂牌国际市场，科研速度 +5%、工坊产出 +5%） → `优先配给`（出口 25%，科研 +2%） → `战时管制封锁`（0% 出口，全部自留，无科研加成）。
- **数据结构**：
  ```ts
  interface DirectiveNodeDef {
    id: string; title: string; days: 28 | 42; x: number; y: number;
    prerequisites: string[]; anyOfPrerequisites?: string[]; mutuallyExclusive: string[];
    availableIf?: ConditionExpr; effects: EffectAction[]; aiWeight: Record<'historical'|'alt', number>;
  }
  ```
- **UI 入口 & AI 使用**：按 `F1` 打开“内政与国家方略公文卷宗”面板；在开启“史实 AI 方略（默认勾选）”时，AI 严格按照预设历史序列队列依次点选节点；关闭史实开关时，AI 按 `aiWeight.alt` 加权随机抽取分支，创造丰富变局。
- **相比 HOI4 精简了什么**：大国树从臃肿的 90–140 个节点瘦身为刀刀见肉的 **20–24 个关键历史抉择节点**，砍掉几十个琐碎的“+1 级铁路”水时长节点，单次周期压缩至 28/42 天，杜绝垃圾等待时间。

### 4.5 历史与动态电报事件系统（Dispatch Event System）

- **玩家可见规则**：
  - 重大历史转折与战争连锁反应通过 **《参谋部加急电报》（Dispatch Modal）** 驱动。每份电报包含：发报日期与地点、简练严肃的 80–150 字历史语境简述、黑白网点几何章/地图微缩聚焦，以及 **1–3 个策略选项按钮**（鼠标悬停按钮精确列出所有数值后果与危机度变动，绝不藏私）。
  - **首发内置 28 个核心事件链**，确保 1936–1945 剧本历史骨架鲜活饱满：
    1. **1936.3 莱茵兰重武装**：`GER` 完成方略触发，`FRA/GBR` 可选择“外交抗议（历史选项，危机度 +5%）”或“武装驱逐（消耗凝聚度立即开战）”。
    2. **1936.7 西班牙内战爆发**：`SPR` 分裂出 `SPA`（控制西属摩洛哥、塞维利亚与北部堡垒省），德意苏法收到电报决定是否派遣“远征志愿军物资包（划拨 1500 步枪 + 1 个作战旅编制支援并获陆战学说加成）”。
    3. **1938.3 德奥合并（Anschluss）** & **1938.9 慕尼黑会议**：英法捷德多方博弈，割让苏台德 3 个山地要塞省或提前引爆中欧大战。
    4. **1939.3 波希米亚肢解与梅梅尔索取**：危机度突破 `50%`，英国自动解锁波兰独立担保事件。
    5. **1939.8 莫洛托夫-里宾特洛甫条约（东欧势力范围密约）**：`GER` 与 `SOV` 签署互不侵犯并约定波兰东西分界线；波兰战役结束时按约移交东波兰省份。
    6. **1939.11 苏芬冬季战争**：苏联索取卡累利阿地峡，芬兰拒绝后触发局部战争（若芬兰坚守 90 天或守住赫尔辛基可触发《莫斯科停战协定》割让边境 2 省体面停战，不强制亡国）。
    7. **1940 法兰西停战协定**：当巴黎陷落且法国本土投降进度达标时，触发历史分治选项（北部与大西洋沿岸由德军占领，南部与北非成立中立傀儡政权“维希行政区 `VIC`”，英国同步触发自由法国抵抗事件）。
- **数据结构**：纯声明式 JSON 事件表 `data/events/europe_events.json`，支持触发器 `trigger: { minDate, completedDirective, provinceControlledBy, fireOnce: true }` 与选项动作集 `options: [{ label, effects, aiChance }]`。
- **UI 入口 & AI 使用**：屏幕正上方滑出带打字机敲击音效的电报纸弹窗（非阻塞普通新闻归入右上电报流水账，需抉择电报自动暂停时间）；AI 在同 Tick 内立即按 `aiChance` 权重与当前国力比做出响应，不阻塞模拟。
- **相比 HOI4 精简了什么**：去除繁琐的“决议倒计时点点乐小游戏”（如议会游说席位、边界小冲突抽奖），将所有叙事与分岔统一收口到清晰的**国家方略 + 电报事件**双轨机制。

### 4.6 工业建设、军需生产线与战略资源贸易（Industry, Production & Trade）

- **玩家可见规则**：
  - **三类核心工业设施（建于 155 个行政工业区 `Region` 上，每个行政区按都市化程度设 `4–12` 个建筑槽位）**：
    1. **民用工坊（Civilian Workshops, `CIV`）**：驱动全国工程建设队列、修复战损设施、支付战略资源进口，并按当前经济法扣除生活消费品比例（`10%–35%`）。每项工程最多同时投入 **`12` 座可用民用工坊**，每座工坊每日输出 **`5.0` 工程点（CP）**，并乘所在行政区基础设施倍率（基建 `1~5` 级分别对应 `×1.0 / 1.15 / 1.30 / 1.45 / 1.60`）。
       - *标准造价表*：民用工坊 `3600 CP`（12 座满编在 3 级基建区约 **46 天** 建成）、军工车间 `2400 CP`（约 **31 天**）、造船船坞 `2200 CP`、行政区基建升级 `1500 CP`、合成炼油所 `3200 CP`（固定提供 `+6 原油`）、省级要塞/港口/防空/空军基地 `900 CP`。战时支持耗费 `900 CP` 将民用工坊快速改建为军工车间。
    2. **军工车间（Military Arsenals, `MIL`）**：分配至 **6 类通用陆空军需产线**，每座车间基础日产 **`4.5` 产能点（IC）**。
    3. **造船船坞（Naval Dockyards, `DOC`）**：分配至护航运输船及三类作战舰艇建造队列，每座船坞基础日产 **`3.5` 海军产能点（NIC）**。
  - **7 类通用军需物资（彻底取消繁琐武器代号仓库，科技研发完成后自动平滑升级全军装备质量而不废弃旧库存！）**：
    | 军需门类 | 单位造价 | 单厂消耗资源 | 主要用途 |
    | :--- | :---: | :---: | :--- |
    | **1. 步兵轻重火器 (`INF_EQ`)** | `0.5 IC` | `1 钢` | 所有陆军旅基础编制与战损补充 |
    | **2. 野战火炮与工兵器材 (`ART_EQ`)** | `2.5 IC` | `2 钢 + 1 稀有金属` | 炮兵支援旅及主力旅火力配属 |

  - **产线熟练度公式（Production Mastery，`20%–100%`）**：
    - 新拨入某类产线的车间初始熟练度为 **`30%`**，每日向熟练度上限 $E_{\max}$（初始 `75%`，工业科技最高提至 `100%`）自然爬升：
      $$\Delta E = 0.012 \times \frac{E_{\max} - E}{E_{\max}} \quad (\text{即从 30\% 爬升至 75\% 约需 90 天})$$
    - 实际日产出 $= N_{\text{factories}} \times 4.5 \times E \times M_{\text{cohesion}} \times M_{\text{tech}} \times M_{\text{resource}}$。因为合并为通用门类，**玩家研发“1940 中型坦克”科技后直接提升装甲旅战斗属性，无需手动切换产线重练熟练度**——只有在把步枪车间临时改产坦克或飞机时才会重置熟练度，既保留了产能转型的战略权衡，又消除了端游每次出新枪都要纠结换线的折磨！
  - **3 种战略资源与“一键自动贸易”**：
    - 全图仅设 **钢铁（Steel）、原油（Oil，兼管海空与装甲出动燃料修正）、稀有金属（Rare Metals，含铝/钨/铬抽象合集）** 三种资源。某项产线若缺资源，每缺少需求量的 `10%` 则该产线产出效率扣减 `-8%`（最差扣至 `-80%`，不会彻底归零卡死）。
    - **贸易极简规则**：每占用 **`1` 座民用工坊** 可从友好/中立出口国购入 **`8` 单位任意资源**（陆路相连免运输船；跨海采购每单占用 `2` 艘护航船）。生产面板内置 **【自动平衡贸易】开关（默认开启）**，系统每日自动根据军工缺口向关系最高且陆路优先的国家下单，玩家亦可手动锁定特定贸易伙伴。
- **数据结构**：`IndustryState { regions: RegionBuildings[]; lines: Record<EquipmentType, { factories: number; mastery: number; stockpile: number }>; autoTrade: boolean }`。
- **UI 入口 & AI 使用**：按 `F3` 打开“军工与建设调度台”，支持横向滑块增减车间与一键置顶抢修；AI 每日运行一次贪心平衡器——根据在编及训练中部队的未来 90 天缺口反推各产线目标工厂配比，每次微调不超过 2 座车间以保护熟练度。
- **相比 HOI4 精简了什么**：资源从 6~7 种减为 3 种且把“原油冶炼燃料池”合并进原油收支平衡；装备型号碎片（步枪 I/II/III、轻坦/中坦/重坦/超重坦及百种改型）凝练为 **7 类通用军需池 + 科技直加成**；加入默认自动贸易解放双手。

### 4.7 人力池与兵役动员系统（Manpower & Conscription）

- **玩家可见规则**：
  - 每个行政区拥有固定基础人口基数（如大伦敦区 850 万、巴黎区 650 万）。全国最大适役人力池公式：
    $$\text{MaxManpower} = \left( \sum_{r \in \text{Core}} \text{Pop}_r + 0.12 \times \sum_{r \in \text{NonCore}} \text{Pop}_r \right) \times R_{\text{conscription}}$$
    *注：非核心占领区仅贡献 **12%** 的人力系数，逼迫扩张国必须权衡本土兵源枯竭风险或扶持合作政权。*
  - **四级兵役征召法（$R_{\text{conscription}}$ 与经济代价）**：
    1. `志愿兵役制（1.5%）`：无任何惩罚（英国及和平中立国默认开局）。
    2. `有限征兵制（3.0%）`：无工业惩罚（法、苏、波、意及 1936 重整军备后的德国常规状态）。
    3. `广泛征兵制（6.0%）`：工厂产出 `-5%`、训练耗时 `+10%`（需处于战争或动员度 ≥50%）。
    4. `倾国动员制（10.0%）`：工厂产出 `-18%`、建造速度 `-15%`、社会凝聚度上限 `-10%`（仅在核心领土遭入侵或总兵力劣势时解锁，模拟战争末期掏空工厂工人的惨烈代价）。
  - 新提升兵役等级后，新增人力并非瞬间到账，而是按每月 **`+0.4%` 总人口** 的动员速率平滑流入可用人力池。每个标准作战旅满编需 **`10,000` 人力**（守备/支援旅 `6,000` 人），新建部队需在后方经历 **35 天（步兵）至 60 天（装甲）** 基础集训方可部署上阵。
- **UI 入口 & AI 使用**：顶栏直接显示可用人力（如 `68.5 万`），悬停展示总适役池、在编人数与累计战损；AI 在可用人力低于在编总兵力的 `15%` 时最高优先级攒 AP 升级兵役法，若已达 `10%` 仍见底则停止新建陆军旅，集中产能补满现有残编部队。
- **相比 HOI4 精简了什么**：省去复杂的新兵训练等级微操（新兵→正规→老兵刷演习耗装备），统一为简洁的标准集训出营 + 实战自动积累老兵星级（最高 `+20%` 攻防）。

### 4.8 蓝晒工程科技树（Cyanotype Tech Tree）

- **玩家可见规则**：
  - **科研槽（Research Slots）**：主要大国开局拥有 **`3` 个并行科研槽**（完成工业/大学方略可解锁第 **`4` 槽**），中小国家开局 **`2` 个槽**（通用方略可升至 **`3` 槽**）。
  - **4 大科技分支，全游戏共 `36` 个高含金量节点**（横向锚定 `1936 → 1938 → 1940 → 1942 → 1944` 五个年代刻度）：
    1. **步兵与火炮工程（9 节点）**：制式步兵火器 I~IV（提升全军软攻与防御）、重型野战炮兵 I~III（提升支援火力与攻坚）、反坦破甲器材 I~II（步兵旅获得硬攻与穿甲加成）。
    2. **机动装甲与机械化（9 节点）**：早期轻战车(1936) → 中型主战装甲(1939) → 倾斜重装甲(1941) → 终极主战坦克(1943)；军用摩托化后勤 I~II；陆战作战学说三选一互斥链（**机动突破学派 / 优势火力学派 / 纵深决战学派**，各 3 阶）。
    3. **海空军备与雷达电子（10 节点）**：单翼全金属战斗机 I~III、近距攻击与战术轰炸 I~II、现代潜艇狼群技术 I~II、水面舰队火控与两栖登陆艇 I~II、无线电密码学与防空雷达链（提供情报视野与本土防空拦截 `+25%`）。
    4. **战时工业与合成化学（8 节点）**：流水线机床 I~III（提高产线熟练度上限与产出）、模块化建筑工程 I~III（提高全国建造速度 `+10%/级` 并增加行政区建筑槽 `+1`）、煤制油合成技术 I~II。
  - **跨年超前研究惩罚公式**：每项科技标有基准历史年份 $Y_{\text{tech}}$ 与基础研发天数 $D_0 \in [75, 135]$ 天。若当前年份 $Y_{\text{now}} < Y_{\text{tech}}$，每提前 1 年研发耗时增加 **`+100%`**：
    $$D_{\text{actual}} = \frac{D_0 \times \left(1 + \max(0, Y_{\text{tech}} - Y_{\text{now}}) \times 1.0\right)}{1 + B_{\text{research\_speed}}}$$
- **UI 入口 & AI 使用**：按 `F4` 打开蓝晒工程图纸面板；AI 按“工业机床/建筑（最高优先） → 当年步炮 → 国家特色分支（如德苏重坦、英美海空）”评分自动填满空闲科研槽，绝不提前超过 0.5 年硬顶惩罚。
- **相比 HOI4 精简了什么**：将原本散落在 8~10 个标签页近 300 个节点的科技海洋，提纯为 **一屏四栏尽收眼底的 36 个核心时代节点**，且将冗长的陆战学说合并进机动分支的 3 阶精炼专精选择。

### 4.9 陆军编制、透明陆战结算与连续战线系统（Land Warfare & Frontlines）

陆战占玩家单局操作体感的 70% 以上。我们用 **“固定标准作战旅模板 + 可视化前锋/支援宽度槽 + 完全透明乘算修正表 + 极简集团军战线”**，彻底革除传统大战略“公式像黑盒、自己跟战线 AI 抢兵”的痛点。

#### 2. 战斗槽位宽度与二线协同规则（融合两作优势）
- 当一个或多个省份向相邻敌军省份发起进攻时，在该敌省触发一场持续性的省级陆战：
  - **基础正面槽位**：单一方向进攻提供 **`4` 个前锋槽（Frontline Slots）+ `2` 个二线支援槽（Support Slots）**（高山/沼泽地形收窄为 **`3` 前锋 + `1` 支援**，都市巷战拓宽为 **`5` 前锋 + `2` 支援**）。
  - **多路侧翼夹击拓宽（Flanking Bonus）**：进攻方每额外从 1 个不同相邻省投入兵力夹击，战场双方向外拓宽 **`+2` 个前锋槽 + `+1` 个支援槽**！这直接鼓励玩家寻找突出部实施三面合围。
  - **预备队轮换**：参战总旅数超出当前槽位上限时，多出的旅置于“预备队列”不受集火但也不输出；每 6 小时 Tick 有 `25%`（无线电科技提至 `45%`）概率自动顶替前锋槽内组织度跌破 `15%` 的疲惫旅。

#### 3. 6 小时 Tick 确定性战斗结算公式
设某个在槽旅基础攻击为 $A_0$（攻方在进攻中比较敌方防御 $D$ 时用自身突破 `Brk` 抵挡敌方火力，守方用防御 `Def` 抵挡攻方火力）：
1. **有效攻防值计算（全透明乘算链，UI 鼠标悬停逐条列出百分比）**：
   $$A_{\text{eff}} = A_0 \times R_{\text{strength}} \times M_{\text{terrain}} \times M_{\text{river}} \times M_{\text{fort}} \times M_{\text{supply}} \times M_{\text{air}} \times M_{\text{plan/entrench}} \times M_{\text{night}}$$
   - 其中 $R_{\text{strength}} \in [0.1, 1.0]$ 为当前人员装备满编率；
   - **堑壕驻防加成**：静止未移动的守军每满 1 天积累 `+3%` 攻防（基础上限 `+24%`，重炮工兵科技可提至 `+33%`）；
   - **攻势筹备加成**：绑定进攻计划并在战线上待命的部队每满 1 天积累 `+3%` 突破与攻击（上限 `+24%`，开打后每日消耗 `-2%`）；
   - **要塞折减**：目标省每 1 级陆上要塞（上限 5 级，如马奇诺防线为 5 级）令攻方 $M_{\text{fort}} = 1 - 0.14 \times \text{FortLevel}$（配属重炮工兵支援旅可抵消 2 级要塞惩罚）。
2. **命中与伤害结算**：
   - 每个参战旅每 Tick 随机锁定对面一个前锋在槽旅（若对方前锋槽已空则直接集火二线支援旅）。
   - **招架减伤机制**：若目标当前剩余防御/突破额度 $G \ge A_{\text{eff}}$，则所有攻击均被有效招架（基础命中系数 `0.10`）；超出招架额度的溢出部分 $(A_{\text{eff}} - G)$ 造成 **3 倍暴击穿透**（命中系数 `0.30`）！
   - **装甲压制红利（Armor Advantage）**：若装甲旅 `Arm` 高于对面目标 `Prc`，该装甲旅受到的组织度伤害乘 **`0.60`**，同时对敌造成的组织度威慑伤害乘 **`1.35`**——直观重现 1940 年缺乏有效反坦火炮的步兵面对坦克集群时的心理崩溃，而一旦步兵研发反坦火箭筒或配属火炮旅穿深达标，装甲光环即告失效。
   - **每 Tick 组织度与编制实力扣减**：
     $$\Delta \text{Org} = \text{EffectiveHits} \times 1.35, \qquad \Delta \text{Strength} = \text{EffectiveHits} \times 0.22$$
     *注：损失的 `Strength` 按 `60%` 转化为人力伤亡、`40%` 转化为军需装备损毁（由后方仓库每日在补给通畅时自动补充）。*

#### 5. 溃退与合围歼灭（Retreat & Encirclement）
- 当前锋槽所有守军旅 `Org ≤ 0` 且预备队无可轮换部队时，防守失败，所有守军自动向相邻的**本方控制且未交战省份**（优先选补给高、距首都近者）撤退，进攻方先头部队进占该省。
- **合围全歼（Pocket Wipeout）**：若战败撤退时，四面所有相邻陆地省均已被敌军控制且本省无友方畅通港口可海运撤离，则被围部队**无法撤退，当场成建制投降覆灭**——损失 100% 剩余在编人力与装备，且进攻方缴获其满编装备量的 **`15%`** 充入己方仓库！地图上触发醒目的红色“合围歼灭 `×N 旅`”战报徽章。

#### 6. 极简不脑溢血的集团军战线与微操融合
- 单层指挥结构：只设 **“集团军（Army，上限 `16` 个旅，可委任 1 位历史/随机指挥官提供如‘装甲先锋 +10%’等单一专长）”**，砍掉繁琐的战区元帅多层嵌套。
- **智能战线绑定但尊重微操**：框选集团军右键点击某段敌国边界即生成**连续战线**，AI 仅在部队空闲时按接壤危险度均匀填满防线缺口；一旦玩家手动框选其中 3 个装甲旅右键连点敌后两省穿插包抄，这 3 个旅自动打上 `manualOverride = true` 锁标，**集团军 AI 在它们抵达终点前绝不擅自把它们拉回原位**，彻底解决端游玩家深恶痛绝的“战线 AI 把快合围的坦克调回后方”顽疾！

### 4.10 简化节点距离补给网络（Simplified Node-Distance Supply）

《钢铁雄心 4》后期的逐格铁轨铺设与枢纽改轨操作对网页端过于繁重，但若完全取消补给（如《文明时代 3》），玩家就会把 80 个旅堆在一个格子里无脑平推莫斯科或北非沙漠。我们设计了**零微操铁轨铺设、但完美呈现后勤极限与断粮合围**的**“多源最短路阻抗补给网”**。

- **玩家可见规则与核心公式**：
  1. **三类天然补给源（Supply Sources）**：
     - **本国首都**：初始补给值 **`S = 100`**；
     - **本土主要工业核心都市（VP ≥ 15）**：补给中继值 **`S = 85`**；
     - **经护航航线连通本土的友方港口（等级 1~5 级）**：提供基础补给 **`S = 35 + 13 × PortLevel`**（如 5 级大港提供 `100` 补给，1 级小滩头港仅提供 `48` 补给，并受途径海区护航效率折减）。
  2. **跨省传播阻抗（每日 `00:00` 执行一次全图多源 Dijkstra，640 省耗时 `< 0.12 ms`）**：
     每跨越一个省份 $(u \to v)$，补给充裕度扣减阻抗损耗 $\text{Cost}(v)$：
     $$\text{Cost}(v) = \frac{\text{BaseTerrainCost}(v)}{\text{InfraMultiplier}(\text{region}_v)} + \text{OccupationPenalty}(v) - \text{TruckBonus}$$
     - `BaseTerrainCost`：平原/都市 `6`、森林/丘陵 `10`、荒漠/沼泽 `15`、高山 `18`；
     - `InfraMultiplier`：1~5 级行政区基础设施分别为 `0.8 / 1.0 / 1.25 / 1.50 / 1.80`（在东线与北非修建基础设施即可显著拉远补给投送半径！）；
     - `OccupationPenalty`：刚攻占不足 14 天的省份带“前线轨距破损”额外阻抗 `+8`，高抵抗占领区额外 `+4`；
     - `TruckBonus`：若国家卡车仓库充裕并开启集团军“摩托化补给配给”，每省阻抗减免 `-3`。
  3. **单省堆叠容量与缺粮惩罚**：
     - 设省份最终算得基础补给值为 $S_p \in [0, 100]$，该省可无损供养的最大旅数为 $\text{Cap}_p = \max(1, \lfloor S_p / 15 \rfloor)$（即满补给省可叠放 `6` 个主力旅不拥挤，荒漠远端 `S=35` 仅能供养 `2` 个旅）。
     - 若驻军数 $N > \text{Cap}_p$ 或 $S_p < 30$，超出部分触发**缺粮状态（Low Supply）**：行军速度最高 `-50%`、组织度恢复停止、攻防战斗力按缺口线性扣减 **`-10%` 至 `-50%`**；
     - **彻底断绝补给（包围圈内无首都且无通航港口，$S_p = 0$）**：被围困满 48 小时（8 Ticks）后，每 Tick 倒扣 `-4` 组织度与 `-1.5%` 装备损耗，攻防固定 **`-60%`**，呈现围困瓮中捉鳖的真实战役张力。
- **UI 入口 & AI 使用**：按 `M3` 切至“后勤补给地图模式”（翠绿 `80–100` → 琥珀黄 `40–79` → 铁锈红 `<40` → 黑红斜纹 `0` 断粮），军牌右上角缺粮时亮起红色油桶叹号；AI 战线分配器严禁向 $N \ge \text{Cap}_p$ 的省份继续增兵，并在攻占港口后最高优先级抢修港口与基建。
- **相比 HOI4 精简了什么**：彻底省去“手动拉鼠标逐省铺 1~5 级铁路线、花半年造补给枢纽、单独生产装甲列车”的繁琐工程，直接将后勤能力锚定在直观的**港口等级 + 行政区基建 + 卡车库存**三要素上。

### 4.11 海军、海区控制与两栖登陆系统（Navy, Sea Control & Amphibious Invasion）

- **玩家可见规则**：
  - **三类抽象海军力量（无舰船改装设计器，按编队规模直接参战）**：
    1. **护航驱逐支队（`DD`，造价 `280 NIC`）**：高反潜侦测，专司保护运输航线与两栖护卫。
    2. **远洋潜艇狼群（`SS`，造价 `240 NIC`）**：高隐蔽破交，专司猎杀敌方跨海贸易与海外补给船队。
    3. **主力水面舰队（`BB/CV` 战列巡洋与航母混编主力，造价 `1400 NIC`）**：提供压倒性海区投射值与海岸炮火支援（对沿岸陆战提供 **`+15%`** 攻防加成）。
  - **10 大海战区任务指派制（无需在地图上微操小船追逐）**：
    将舰队编组指派至最多 2 个相邻海战区执行三选一任务：**① 夺取制海权（Fleet Dominance）**、**② 航线护航（Convoy Escort）**、**③ 破交封锁（Convoy Raiding）**。
    - **海区控制度公式**：某阵营在海区 $z$ 的控制占比为：
      $$\text{SeaControl}_A(z) = \frac{P_A(z)}{P_A(z) + P_B(z) + 20} \quad \left(P = 12 \cdot N_{\text{BB/CV}} + 3 \cdot N_{\text{DD}} + 1.5 \cdot N_{\text{SS}} + 0.5 \cdot N_{\text{NavalAir}}\right)$$
    - 双方在同一海区均指派水面舰队时，每日有 `15%` 概率触发**海上交锋结算**，按火力比与防空值削减舰艇耐久或击沉舰只，重伤舰只自动退回母港船坞维修。
  - **两栖登陆规则（Amphibious Assault，开辟诺曼底/西西里/北非战场的关键）**：
    1. 选中驻扎在己方港口省的集团军（单次登陆上限 **`6` 个旅**，科技解锁登陆艇后提至 **`12` 个旅**），点击目标敌方沿海省下达“两栖突击令”；
    2. 需满足三个硬前提：① 筹备期满 **`21 天`**（每旅籌备 3.5 天，合并上限 21 天）；② 仓库空闲护航运输船 **`≥ 5 艘 / 旅`**；③ 途经所有海战区的本阵营 **`SeaControl ≥ 55%`**；
    3. 抢滩战斗承受基础 **`-40%` 滩头涉水惩罚**（山地旅与两栖科技可减免至 `-15%`）。**一旦成功登岸，必须在约 10 天内夺取邻近港口省**，否则无港滩头补给迅速耗尽陷入绝境！
- **UI 入口 & AI 使用**：按 `M5` 或点击海洋打开海战区态势条；英国/意大利 AI 将 60% 船坞投入护航与主力舰守卫地中海与大西洋生命线，德国 AI 将 80% 船坞产能量产潜艇在大西洋/比斯开湾执行破交；当同盟国在 1942 年后陆军充裕且握有英吉利海峡/中地中海制海权时，AI 自动策划针对西西里或法国北部的成建制两栖登陆。
- **相比 HOI4 精简了什么**：砍掉索敌巡逻分队与主力打击分队分离配置、索敌航速匹配、水雷布扫雷、火控雷达部件拼装等令 90% 玩家头疼的海军黑盒，浓缩为直观的**“三种舰船 + 海区控制百分比条 + 21 天登陆筹备”**。

### 4.12 空军、制空权与战略轰炸简化系统（Air Superiority & Support）

- **玩家可见规则**：
  - 军工车间生产的 **`战术与制空战机 (AIR_TAC)`** 与 **`战略轰炸机 (AIR_STR)`** 直接汇总在国家空军池中，每 **`50` 架** 组成 1 个标准飞行大队，指派进 **18 个战略陆空区**（需该区或紧邻区拥有己方空军基地，每级基地容量 `2` 个大队，超出容量出动率减半）。
  - **区域制空比与三大直接战场效果**：
    设本方在空域 $z$ 投入制空战机数为 $F_A$，敌方为 $F_B$，制空比 $R_{\text{air}} = \frac{F_A}{F_A + F_B + 50}$：
    1. **夺取制空权（$R_{\text{air}} \ge 0.60$）**：该区所有敌方陆军行军速度 **`-20%`**，敌方陆战防御/突破 **`-15%`**；
    2. **近距对地支援（CAS）**：勾选“对地支援”的战术战机大队直接参与本空域内正在进行的陆战，最高为己方陆军提供 **`+20%` 额外攻击修正**并对敌军直接造成每 Tick 微量组织度杀伤；
    3. **战略轰炸（Strategic Bombing）**：战略轰炸机大队每日对敌控空域内的工业区与基础设施造成工程毁伤（每日炸毁 `15–40 CP` 建筑耐久，迫使敌方民用工坊分流去抢修），若敌方在该区拥有制空优势或省级防空炮，轰炸机每日承受 `2%–6%` 击落战损。
- **相比 HOI4 精简了什么**：无需手工在几十个机场之间来回搬运几百架飞机的联队编制，改为**“战略空域一键滑动增减飞行大队配额（后台自动就近分配机场）”**，3 秒即可完成整个东线或英伦空战部署！

### 4.13 占领政策、抵抗运动与附庸政权（Occupation, Resistance & Puppets）

- **玩家可见规则**：
  - 攻占敌国非本国核心（Non-Core）的行政区后，该区进入**战时军事占领态**（地图显示占领斜纹），拥有独立的 **`抵抗度 (Resistance, 0%–100%)`** 与 **`顺从度 (Compliance, 0%–100%)`**。
  - **后台抽象治安驻防（免除满地图摆小警察的垃圾微操）**：系统每日自动从国家人力池与步兵火器库按活跃占领区数量划拨“治安宪兵配额”（每个占领行政区基准需 `1,500 人力 + 15 步枪`）。若枪支或人力断供，当地抵抗度每日暴涨 `+0.8%`！
  - **三档占领法令（可在国情占领总览表按国家一键设定）**：
    | 占领政策 | 可用当地工厂比例 | 可用当地资源比例 | 治安人力消耗倍率 | 抵抗目标平衡值 | 顺从度日增长 |
    | :--- | :---: | :---: | :---: | :---: | :---: |
    | **1. 民事自治绥靖** | `25%` | `35%` | `×0.7` | `15%`（低危） | **`+0.12%/日`** |
    | **2. 标准战地军管** | `45%` | `60%` | `×1.0` | `35%`（中危） | `+0.06%/日` |
    | **3. 战时强征管制** | **`65%`** | **`85%`** | `×1.6` | `60%`（高危） | `0%/日` |
  - **抵抗度阈值后果**：抵抗度 `≥ 30%` 时该区补给传输阻抗 `+4`；`≥ 60%` 时每月随机破坏 `1` 座当地工坊/基建并造成驻军 `3%` 额外伤亡；`≥ 90%` 时触发武装起义（在该区核心都市刷出 2 个敌对游击步兵旅切断后方补给线！）。反之，顺从度每积累 `20%` 额外解锁 `+10%` 当地工厂利用率。
  - **建立自治附庸国（Puppet / Associated State）**：占领某亡国政权全境（或通过战后和约）可将其释放为本阵营附庸国——瞬间消除全部抵抗治安负担，附庸国自动采用宗主国政体、将 `25%` 民用工坊与 `50%` 富余战略资源无偿上缴宗主国，并自行运用核心人力训练本土守军协同作战。
- **相比 HOI4 精简了什么**：将 9 种琐碎占领法案浓缩为定位极清晰的 **3 档**，保留广受好评的后台自动扣减枪支人力机制，避免地图上塞满几百个驻防骑兵师。

### 4.14 投降判定、简化和约会议与胜利终局（Capitulation, Peace & Victory）

- **玩家可见规则**：
  1. **国家投降公式（Capitulation）**：每个核心省份依城市规模赋予胜利点（`VP`：首都如柏林/伦敦/莫斯科 `30–50 VP`，重镇 `10–20 VP`，次要城 `3–5 VP`，普通乡村省 `0–1 VP`）。当某国仍在己方控制的**本土核心 VP 占比**跌破其投降阈值 $T_{\text{cap}}$ 时，次日 `00:00` 宣告本土投降：
     $$T_{\text{cap}} = \text{clamp}\left(0.20 - 0.15 \times (\text{Cohesion} - 0.50),\; 0.08,\; 0.35\right)$$
     *典型实例*：法国 1939 开局社会凝聚度偏低（`38%`），投降阈值为 `21.8%`——一旦德军突破阿登夺取巴黎及北方工业重镇（占法国本土约 79% VP），即触发历史性投降或维希停战电报；而卫国战争中的苏联凝聚度与动员度拉满，投降阈值低至 **`10%`**，即便丢掉明斯克、基辅乃至逼近莫斯科仍可退守伏尔加-乌拉尔继续死战！
  2. **阵营存续与和约触发**：若被击败国属于三大阵营之一，且该阵营仍有至少 **1 个未投降的主要大国（Major Power：`GER/GBR/FRA/SOV/ITA`，以及后续参战的场外美援实体或工业破 80 厂的新晋大国）**，则投降国转为“流亡抵抗状态”，领土暂归占领军军管；**一旦敌方阵营最后一个主要大国投降，整场阵营大战宣告胜利终结，立即弹出《欧洲善后和约大会》！**
  3. **单屏两轮制简化和约会议（Peace Conference）**：
     - 各战胜国按战争累计贡献（歼敌旅数 `40%` + 攻占敌 VP `40%` + 战略轰炸/护航贡献 `20%`）分配 **和约发言权点数（Peace Score）**。
     - 摒弃动辄点击几十轮、造出奇丑飞地边境（Border Gore）的碎片拍卖，改为 **以“行政工业区（Region，共 155 区）”为最小割让颗粒度的两轮竞价面板**：战胜国依次消耗点数执行 **① 直接吞并边疆区（核心宣称区半价）**、**② 变更政体并纳为阵营附庸国**、**③ 解放被吞并国家（如复国波兰/捷克/奥地利，宪政大国执行此项获额外胜利分）**、**④ 五年工业赔款（划拨战败国 20% 民用工坊产能）**。AI 严格遵循“连通性邻接约束”，绝不在内陆随机抠一块无港口飞地。
  4. **战役终局与胜利评级**：达成“本阵营独霸欧洲（其余两大阵营均已战败或解散）”时可立即触发提前史诗胜利（亦可选择继续沙盘游玩）；或运行至 **`1945-12-31 24:00`** 弹出《十年历史档案总结册》，按阵营总工业、控制 VP、科技领先度与低伤亡比评定 `S / A / B / C` 历史统帅评级，并绘制一幅 1936–1945 版图演变延时回放小动画。

## 5. AI 对手架构设计（三层效用评估与战役状态机）

大战略游戏单机体验的成败一半系于 AI：既不能像木桩一样任人宰割或排兵漏出空城首都，也不能因过度消耗算力拖慢后期帧率。本项目采用 **“三层分层效用评分（Hierarchical Utility AI）+ 时间切片轮询（Time-Sliced Staggering）”** 架构，完全运行于 `SimulationWorker` 内，使用与玩家完全相同的 `GameCommand` 接口（零特权读取未探明敌后迷雾外隐藏指令，仅在最高难度获透明数值加成）。

---

### 5.1 战略层 AI（Strategic Layer：每 7 游戏日评估 1 次）

负责决定“谁是潜在盟友、谁是头号威胁、何时陈兵边境并宣战”：
1. **邻国威胁与目标评分（Threat & Target Scoring）**：
   对每个国家 $B$ 计算战略姿态权重：
   $$U_{\text{hostile}}(A \to B) = W_{\text{core\_claim}} + W_{\text{directive\_goal}} + 40 \cdot \text{RegimeClash} - 35 \cdot \left(\frac{\text{Power}_{B+\text{Allies}}}{\text{Power}_{A+\text{Allies}}}\right)$$
   - **反自杀宣战熔断锁（Anti-Suicide Guardrail）**：若 $A$ 当前已在与至少一个主要大国交战且战线处于净丢省劣势（近 30 天丢失 VP > 获得 VP），**强制冻结一切开启新战线的主动宣战指令**！这直接避免了端游中常见的“德国在西线尚未击败法国时又机械死板向苏联和南斯拉夫同时宣战瞬间暴毙”的经典蠢招（例如：德国 AI 只有在 `FRA` 本土已投降、或时间已过 1941.6 且西线陆地无活跃敌军时，才会激活东线作战方略）。
2. **外交与阵营抉择**：
   - 当某中小国家（如比利时、希腊、罗马尼亚）自身受邻国宣称威胁或遭入侵时，自动向意识形态相近或敌对侵略者的阵营盟主申请入盟/寻求担保。
   - 中立缓冲国（瑞士 `SWI`、瑞典 `SWE`、土耳其 `TUR`、爱尔兰 `IRE`）拥有极高的中立定力修正（`neutralityBias = +120`），除非直接遭到宣战或危机度达 `95%` 且被特定架空方略拉拢，否则严守历史中立。

### 5.2 经济与科研层 AI（Economic & Tech Layer：每 14 游戏日评估 1 次）

采用可配置的数据驱动 **国家经济人格模板（`AIProfile`: `continental_armor` 陆权装甲型、`maritime_air` 海空护航型、`deep_defense` 纵深人力型、`minor_balanced` 均衡自卫型）**：
1. **民用建设两阶段状态机**：
   - **第一阶段（和平期且距离预期开战年 `> 1.5 年`，如 1936–1937.6）**：`75%` 工程队列在基础设施 `≥ 3` 级的安全腹地扩建 **民用工坊（`CIV`）** 滚雪球，`25%` 修建关键工业区基建或合成炼油所（针对缺油的 `GER/ITA`）。
   - **第二阶段（临战期或已处于战争）**：立即将 `80%` 工程队列切为扩建 **军工车间（`MIL`）**，剩余 `20%` 用于前线港口扩容、受轰炸建筑抢修或在受威胁首都外围补筑 1~2 级要塞。
2. **生产线动态配比算法**：
   - 统计所有在编旅 + 训练队列的装备缺口 $\text{Deficit}_k$ 与过去 30 天平均日战损 $\text{Burn}_k$，计算每类军需的紧急度 $P_k = \frac{\text{Deficit}_k + 45 \cdot \text{Burn}_k}{\text{UnitCost}_k}$。
   - **步枪底线铁律**：一旦步兵轻重火器（`INF_EQ`）库存为负，强制至少拨给步枪产线 `45%` 军工车间，确保前线填线步兵绝不赤手空拳；每次调整单条产线增减不超过 `2` 座车间，避免频繁洗掉产线熟练度。
3. **科研优先级**：第 1 槽永远锁定工业机床与建筑工程；第 2 槽锁定当年步炮与陆战学说；第 3/4 槽按人格分配给中型坦克（`GER/SOV`）或雷达战斗机与护航驱逐舰（`GBR`）。

### 5.3 军事战役层 AI（Operational & Tactical Layer：每日分片评估）

这是玩家直观交手的重心，拆解为四个严密协同的子模块：
1. **防线与海岸驻防分配器（Theater Allocator）**：
   - **首都与核心大港死守保留队（Garrison Reserve）**：任何沿海国或交战国必须优先抽调总兵力的 `15%`（优先使用 `GAR` 守备旅）钉死首都及等级 `≥ 3` 的本土港口省，彻底杜绝玩家派 1 个摩托化旅偷船空降无人伦敦或罗马的投机漏洞。
   - 剩余野战主力按各段边境的 `敌军接壤兵力 × 1.2 + 目标战略权重` 比例分配至各条连续战线，保证**接壤前线每一个省份至少有 1 个旅驻防，绝不留空省漏洞**！
2. **三态战役节奏机（`HOLD_ENTRENCH` → `PREPARE_SHOCK` → `EXPLOIT_POCKET`）**：
   - **严禁无脑全线平推耗干人力**！当战线总体兵力装备比 `< 1.05` 或组织度均值 `< 55%`、或处于东欧严冬/泥泞季时，战线切入 `HOLD_ENTRENCH`（全线掘壕死守攒组织度，仅对敌方暴露孤立弱点做局部反击）。
   - 当筹备加成攒满 `≥ 18%` 且局部兵力优于当面守军时，AI 将麾下 **装甲旅 (`ARM`) 与摩托化旅 (`MOT`) 集中编为 1~2 个矛头突击群**，专门挑选**平原/丘陵且无大河阻隔**的 2 个相邻敌省发起多路侧翼夹击（吃满宽度拓宽红利）。
   - **反包围逃生本能（Anti-Pocket Reflex）**：每日扫描己方突出部省份——若某省通往首都的补给走廊仅剩 **唯一 1 个咽喉省份** 且该咽喉省正在遭受优势敌军围攻，突出部顶端部队立即放弃阵地向后收缩 1 省拉直战线，大幅提高玩家合围 AI 的博弈含金量！
3. **海空协同 AI**：空军优先将 `70%` 战斗机大队压在当前爆发战斗最多的陆战空域争夺制空权；同盟国两栖登陆 AI 遵循“集结满 8–10 个精锐旅 + 确保英吉利海峡/西西里海区控制度 ≥65% + 直扑带港口的沿海省并在登岸次日后续梯队跟进扩港”的完整剧本逻辑。

### 5.5 无头 AI 自对弈调参管线（Headless Self-Play Tuning）

开发脚本内置 `scripts/ai-arena.ts`：一次命令在 Node 多核进程池并行跑完 **50 局 1936–1945 全 AI 史实模式对战（约耗时 20 秒）**，自动输出统计看板 JSON：
- **核心验收校准区间**：① 德军在 1939–1940 击败波兰概率 `> 92%`、在 1940–1941 击败法国本土概率 `70%–85%`；② 苏德战争在 1941 爆发后，至少 `80%` 对局能持续拉锯至 1943 年以后（既不出现 1941 冬德军 3 个月平推乌拉尔，也不出现德军卡在波兰边境寸步难行）；③ 英美盟军在 1943–1944 成功实施至少一次规模化西欧或意大利两栖登陆的概率 `> 65%`。若偏离区间，编码 Agent 仅需微调 `data/balance/combat_defines.json` 中的防御招架系数或补给阻抗常数即可快速收敛平衡。

## 6. UI/UX 交互与原创界面架构（Information Architecture & Wireframes）

### 6.1 原创“战时参谋桌面三锚点”布局（绝不复刻参考作 UI）

传统大战略界面常犯两大通病：一是像《钢铁雄心 4》那样在左上角铺满两排琐碎数字、左侧弹出两层宽大级联面板遮死半张地图、底部摆一长溜将领肖像；二是像《文明时代 3》那样四周贴边围一圈细碎按钮并在右下角塞一块占地方的矩形世界小地图（对单战区地图完全多余）。

《子午线 1936》提出**“地图即桌面，面板即公文夹”**的原创**三锚点悬浮信息架构（Three-Anchor Floating Desk）**，确保常态下 **88% 屏幕面积**、展开抽屉时 **73% 屏幕面积** 完全归属参谋地图：
1. **锚点一：顶栏双翼分体简报笺（Split Top Header，中央留空）**：
   - **左上“国家印鉴与核心国力笺”**：左侧嵌中性国旗与政体章，向右依次紧凑排列 5 组等宽对齐核心数据：`行政点 AP`、`凝聚度 / 动员度`、`可用人力`、`工厂总数 (民/军/船)`、`三项战略资源净余量（钢/油/稀，缺口标朱砂红）`。
   - **右上“参谋怀表与危机气压计”**：显示当前精确日期与时段（如 `1939年 9月 1日 · 拂晓 06:00`）、暂停与 `1x~4x` 机械拨杆、以及一枚半圆形指针表盘 **“欧洲危机度 `42%`”**。顶栏正中央完全透明留白，绝不压迫地图视野。
2. **锚点二：底部居中“公文卷宗坞站 + 透镜组”（Bottom Center Command Dock）**：
   - 屏幕下沿居中悬浮一条温润深胡桃木与黄铜包边底座：左半区为 **6 枚梯形档案夹标签**（`[F1 方略]` `[F2 外交]` `[F3 军工]` `[F4 科技]` `[F5 占领/补给]` `[F6 集团军]`，有空闲槽位如未选方略或空闲科研槽时，对应夹签边缘浮现柔和琥珀呼吸点而非刺耳感叹号轰炸）；右半区紧邻 **6 枚圆形制图透镜按钮** 一键切换地图模式（`M1~M6`）。
3. **锚点三：右侧单层参谋抽屉（Right Context Drawer，固定最大宽 `380px`）**：
   - **全游戏严格执行“同一时刻最多展开一个右侧单层抽屉”铁律**（仅全屏树状图如“国家方略树”与“蓝晒科技树”采用中央半透明磨砂纸卷模态框 `960×640px`，按 `Esc` 或点空白秒关）。点击任何底部夹签、点击地图省份或点击交战气泡，统一在右侧抽屉平滑切换内容，视线动线高度统一，且对右手鼠标/平板右手拇指操作极度舒适！

### 6.4 通知分级与防打断电报流（Non-Intrusive Notifications）

策略游戏最忌每分钟弹出三四个无关紧要的“某小国签署贸易协定”窗口打断玩家划线思路。我们将全局信息严格切分为三级：
1. **一级：加急参谋电报（Modal Dispatch，强制暂停时间）**：仅限**本国或盟友被宣战、需要玩家二选一拍板的历史分岔事件、核心首都濒危、两栖敌军在本土抢滩登岸、阵营终局和约**。从屏幕上沿滑下带邮戳电报纸卡片，必须点击选项后方可恢复时间。
2. **二级：右上电报流水纸带（Ticker Tape，不暂停时间）**：位于右上角怀表下方，最多叠放最近 **4 条单行简讯**（如 `✦ 科研完成：中型主战装甲 (1939)`、`⚡ 华沙被第 1 装甲军攻占`、`📜 意大利与匈牙利缔结防御协定`），5 秒后自动半透明归档进“战史大事记抽屉”，点击该条简讯摄像机自动平滑飞跃至事发省份。
3. **三级：卷宗呼吸角标（Silent Badge）**：空闲科研槽、未指派国家方略、可用民用工坊闲置、某类装备出现负库存缺口，统一表现为底部对应卷宗夹签右上角的**暖琥珀圆点与数字徽标**，绝不弹窗吵闹。

## 8. 音频与动态声景设计（Audio & Dynamic Soundscape）

大战略玩家单局停留长达 2–4 小时，音频绝不能吵闹刺耳或单曲死循环令人生厌，而应营造 **“身处 1930 年代深夜作战参谋室：远处电报机微响、铅笔划过亚麻地图、窗外时代风云渐起”** 的沉浸质感。本项目基于原生 **Web Audio API** 封装轻量级 `SoundEngine`（无需引入重型第三方音频库），兼具极小包体与高可靠性。

---

### 8.1 三态动态音乐分层状态机（Adaptive Music State Machine）

背景音乐随全局 **欧洲危机度（Crisis Index）** 与 **本国是否处于大国战争** 自动平滑演进，切换时执行 **`3.5 秒` 等功率交叉淡入淡出（Equal-Power Crossfade）**，并在曲目间插入 **`8–15 秒` 自然留白呼吸期**（模仿古典留声机换碟节奏，大幅缓解听觉疲劳）：

1. **第一层：战间和平期（`PEACE_ERA`：本国未参战 且 危机度 `< 40%`）**：
   - **听感定位**：克制、思辨、略带旧时代怀旧感的大提琴与室内管弦慢板（如德沃夏克《新世界》第二乐章慢板、巴赫/埃尔加弦乐公有领域录音，Opus 96kbps 压缩）。
2. **第二层：暗流危机期（`CRISIS_TENSION`：本国未参战 但 危机度 `≥ 40%`，或正在拟定最后通牒）**：
   - **听感定位**：悬疑紧绷的低音提琴拨弦、定音鼓微弱脉动与持续低频铺底（Incompetech CC-BY 4.0 悬疑管弦曲目），预示风暴将至。
3. **第三层：全面战争期（`TOTAL_WAR`：本国正与主要大国交战）**：
   - **听感定位**：庄重厚重的铜管与交响进行乐章（如霍尔斯特《行星组曲·火星》或贝多芬第七交响曲第二乐章公有领域管弦录音——庄严肃穆而非欢快军国进行曲，契合严肃历史反思基调）。
- **按需流式懒加载（Lazy Streaming）**：首屏仅加载 UI 音效（`< 120 KB`），背景音乐 `.ogg/.mp3` 文件（共 6–8 首，总计约 `9 MB`）在首屏可交互后通过低优先级后台流式加载，完全不阻塞地图秒开。

### 8.3 混音总线、鸭子闪避（Ducking）与浏览器自动播放策略

1. **四路独立混音总线（Audio Mixer Buses）**：
   - `Master（总音量，默认 80%）` 下辖三路子增益节点：`Music（配乐，默认 55%）`、`UI & Dispatch（界面与电报，默认 85%）`、`Battle Ambience（前线环境，默认 60%）`，右上角设置小齿轮支持一键全局静音（快捷键 `M`）并实时持久化至 `localStorage`。
2. **动态闪避与防爆音并发锁（Ducking & Polyphony Cap）**：
   - **电报闪避**：当一级加急电报（如宣战通牒）弹出时，`Music` 总线自动在 `150ms` 内压低 `-6 dB`，待玩家阅读关闭电报后在 `800ms` 内恢复原音量，突出历史抉择仪式感。
   - **严格并发上限**：在 4x 极速推进时，同一种音效（如省份占领提示、科技完成提示）在 `300ms` 窗口内最多触发 **1 次**（自动合并跳过重叠请求），全局同时发声的 SFX 通道上限锁死为 **6 路**，彻底杜绝高速跳天时出现刺耳的音效叠音爆鸣。
3. **浏览器 Autoplay Policy 优雅解锁**：
   - 遵循 Chrome / Safari 音频安全规范，页面加载时不强行调起 `AudioContext` 报错，而是在玩家**第一次在选国界面或标题页发生任意 `pointerdown / keydown` 交互事件**的同步回调内静默调用 `audioCtx.resume()` 并柔和渐入标题界面主题曲。

### 10.3 内存、显存（VRAM）与 Draw Call 硬约束

平板 Safari 若单页显存与堆内存超过 ~400MB 极易被系统强杀刷新页面，故制定严苛上限：
1. **JS 主线程 + Worker 总堆内存（JS Heap）`≤ 95 MB`**：
   - `SimulationWorker` 核心状态采用结构体数组（SoA / TypedArrays）与对象池复用，每 Tick 严禁新建数千个临时 `{ x, y }` 小对象，杜绝锯齿状 GC 停顿；历史命令回放日志每满 1,000 条自动用 `fflate` 增量归档压缩。
2. **GPU 显存占用（VRAM）`≤ 110 MB`**：
   - `province_id.png` (`4096×3072` RGBA8 = `48 MB` VRAM) + `terrain_relief.webp` (`2048×1536` RGBA8 = `12 MB` VRAM) + 一张合并好的 `2048×2048` UI/军牌/图标/MSDF 字形纹理图集（Atlas，`16 MB` VRAM）+ 帧缓冲，总显存稳控在 **90 MB 左右**！
   - **平板自适应降级**：检测到 `navigator.maxTouchPoints > 0` 且屏幕短边 `< 900px` 时，自动将 PixiJS `resolution` 锁顶在 `Math.min(window.devicePixelRatio, 1.5)`，节省 44% 片元填充率开销。
3. **每帧 WebGL Draw Calls `≤ 25 次`**：
   - 地图底色+政区 LUT 合成：**1 Draw Call**；
   - 国界/省界/河流静态与动态丝带网格：**3 Draw Calls**；
   - 战线与进攻贝塞尔箭头合批网格：**2 Draw Calls**；
   - 全图最多 300 个可见堆叠军牌与城市微标（共享单张 `2048²` Sprite Atlas）：PixiJS v8 自动合批为 **2–4 Draw Calls**；
   - 国名与城市 BitmapText：**2 Draw Calls**。
   - 全场景合计仅 **~12 次 Draw Calls**，即便在无硬件加速的 **SwiftShader 软光栅沙盒** 中也能流畅截图与交互！

### 12.2 数据驱动 Schema 规范与多战区/Mod 扩展接口

所有规则配置杜绝写死在 TS 分支中，统一遵循可组合的 **`ConditionExpr`（条件谓词）+ `EffectAction`（原子动作）+ `Modifier`（数值修饰符）** 三元 JSON 契约。以国家方略节点为例：
```json
{
  "id": "ger_synthetic_fuel",
  "title": "洛伊纳合成燃油扩建",
  "days": 42,
  "col": 2, "row": 3,
  "prerequisites": ["ger_four_year_plan"],
  "mutuallyExclusive": [],
  "availableIf": { "ownsRegion": "reg_saxony" },
  "effects": [
    { "type": "ADD_BUILDING", "region": "reg_saxony", "building": "SYNTH_REFINERY", "count": 2 },
    { "type": "ADD_TECH_BONUS", "category": "industry_chem", "bonusPermille": 500, "uses": 1 }
  ],
  "aiWeight": { "historical": 100, "alt": 90 }
}
```
- **亚太第二战区与全球战役无缝接口**：`TheaterManifest` 定义了战区坐标宽高、省份 ID 起止偏移（欧洲 `1..1999`，亚太 `2000..3999`）以及边缘跨图航道节点（`offmapEdges: [{ fromProv: 612 /* 苏伊士南口 */, toTheater: "pacific_1937", toProv: 2015 /* 红海-印度洋航道 */, transitDays: 14 }]`）。未来挂载亚太包时，只需在 `theaters.json` 新增一项，引擎即可直接加载亚太地图单独游玩，或在“全球合流模式”下拼接两张纹理/邻接图联合演算！
- **轻量自定义剧本 / Mod 导入**：主菜单提供“加载自定义数据包（`.json`）”实验开关，玩家修改任意国家的起始工厂或自创架空方略树 JSON 拖入浏览器，经 Schema 校验通过即可立即开玩。

### 13.2 “如果开发周期/预算只能留一半，先砍什么？”（50% 范围裁剪应急优先级）

假设在实际分批执行中，用户希望将批次压缩一半（如 6 批内极速上线 MVP v0.5）或某阶段需要果断止损保核心品质，**严禁把每个系统都做个半吊子空壳**，必须按下方**从先砍到死保**的顺序干净整块剥离：

#### 第一顺位优先砍掉（砍后完全不伤核心陆战与版图涂色爽感，省下 ~30% 工作量）：
1. **砍掉 1939《风暴前夜》第二套起始数据表**：只集中全部精力把 **1936《暗流涌动》** 单剧本打磨到极致。
2. **将“两轮制积分竞价和约会议”降级为“历史/全吞并二选一电报结算”**：敌方阵营战败时直接弹出历史分治方案或由主导战胜国按占领线直接划定疆界，省去复杂多国竞价 UI。
3. **将“占领区动态抵抗度/顺从度与三档政策”降级为固定系数**：简化为“非核心占领区固定提供 `35%` 工厂、`50%` 资源与 `10%` 人力”，省去整套治安驻防抽屉。
4. **收窄次要国家定制内容**：保留 **德、英、法、苏、意 5 大国专属方略树**，波兰与其余 24 国统一共用 16 节点通用方略树；历史电报事件从 28 链浓缩为 **12 条主干必发事件**（莱茵兰、德奥、慕尼黑、苏德条约、但泽开战、法兰西停战、巴巴罗萨等）。

#### 第二顺位可大幅抽象（再省 ~20% 工作量，退守纯粹欧洲大陆战争核心）：
5. **海空系统极致抽象为“国家军备池滑块 → 战区开关”**：砍掉 3 种独立舰船建造队列与战略轰炸机分支，合并为单一“海空支援产能条”——只要本国海空军备点数高于当面敌国，即在对应沿海/前线获得制海通行权与 `+15%` 制空支援修正，无需专门的 `AirSeaDrawer` 复杂交互。
6. **资源从 3 种再压至 1 种核心战略物资（“原油/燃料”）**：钢铁与稀有金属直接内化进工厂造价，只保留决定装甲集群与空军能否全速推进的“原油”博弈（罗马尼亚普洛耶什蒂与高加索巴库争夺战依然成立！）。

#### ★ 绝对不可妥协、哪怕只剩一半资源也必须 100% 保住的“产品生命线”：
- **高颜值亚麻纸质参谋地图（PixiJS LUT 着色器 + 水彩边缘晕染 + 弯曲国名 + 中性合规旗帜）**；
- **Web Worker 6 小时确定性 Tick（暂停 + 4 档倍速丝滑不卡）**；
- **可见连续战线 + 钳形进攻箭头 + 透明前锋/支援槽位陆战结算 + 合围口袋全歼**；
- **多源距离衰减补给线（防无脑叠兵）+ 民用工坊/军工车间宏观备战节奏 + 靠谱不犯蠢的陆战 AI**。
只要守住这四根支柱，哪怕砍掉全部外围枝叶，《子午线 1936》依然是一款画面惊艳、机制自洽、让人欲罢不能的二战欧洲大战略精品！

## 附录 B：原创术语与机制对照总表（Terminology & Identifier Glossary）

为确保全项目从代码变量名（TypeScript Identifiers）、JSON 数据表键名到中文玩家界面文案 **100% 保持原创辨识度与内部一致性**，绝不直接照搬参考作的专属术语（如“国策 / 政治点数 / 民用工厂 / 世界紧张度 / 法西斯主义”等原词），编码 Agent 须严格遵循下表命名：

| **议会宪政制** | `Constitutional Republic` (`republic`) | 西方代议制政体路线 | 高科研与贸易信用，低危机度下受和平主义约束 |
| **集权军国制** | `Militarist Autocracy` (`autocracy`) | 扩张型极权军国路线 | 宣战筹备极快、计划加成高，但逆风丢失本土易崩盘 |
| **计划动员制** | `Planned Collectivism` (`collectivist`) | 集中计划工业政体路线 | 重工槽位与资源自给加成高，初期需方略整肃军官团 |

| **产线熟练度** | `Production Mastery` (`mastery`) | 生产线连续制造效率 | 新线 `30%` 起步，随天数爬升至 `75%~100%`；同门类科技升级不掉熟练度 |
| **稀有金属** | `Rare Metals` (`RARE`) | 铝 / 钨 / 铬等特种工业矿产合集 | 与钢铁（`STEEL`）、原油（`OIL`）共同构成三大战略资源 |

| **编制实力 / 组织士气** | `Strength` / `Organization` (`Org`) | 单位人员装备完整度 vs 战斗意志条 | 实力扣减造成真实伤亡损毁；组织士气归零触发撤退或被围全歼 |

| **节点补给充裕度** | `Supply Adequacy` (`S_p`) | 省份后勤供养能力值 | `0–100`，由首都/大都市/港口经多源最短路按地形与基建阻抗衰减 |
